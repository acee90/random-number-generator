## 목표

사이트의 첫 목적을 **함께 점심 식당을 추첨하는 서비스**로 바꾼다. 첫 화면에서 방을 만들고, 링크로 들어온 동료가 바로 참여하며, 룰렛·결과·후보·채팅을 한 흐름에서 확인하게 한다. 기존 숫자·복권 도구와 혼자 추첨하는 기능도 유지한다.

현재 `/`는 번호 도구, `/lunch`는 단독 룰렛과 모달 방 생성 화면이다. 실시간 방은 이미 구현돼 있다. 이번 전환은 기존 난수 엔진과 방 서버를 유지하면서 경로, 첫 화면, 방 화면의 우선순위를 바꾸는 작업이다.

브랜드는 **점메추 / Jeommechu**, 표시 도메인은 `jeommechu.dev`를 기준으로 정리한다. 이번 범위는 화면의 브랜드와 제목·설명 등 메타데이터다. 도메인 구입, DNS 변경, 사용자 지정 도메인 연결, 배포·공개는 별도 작업이다.

## 경로와 상단 탐색

| 경로 | 역할 | 전환 내용 |
| --- | --- | --- |
| `/` | 점메추 메인 | 방 이름·내 닉네임·방 만들기를 화면에 바로 제공한다. 공동 추첨이 주 행동이다. |
| `/tools?tool=number` | 랜덤 숫자 | 현재 숫자 생성기를 옮긴다. `/tools`의 기본 도구도 `number`다. |
| `/tools?tool=lotto` | 로또 6/45 | 번호 분산·고정·제외 등 현재 기능을 유지한다. |
| `/tools?tool=pension` | 연금복권 720+ | 조 선택과 현재 생성·복사·기록 기능을 유지한다. |
| `/solo` | 혼자 점심 추첨 | 기존 개인 룰렛과 브라우저 기록을 유지한다. 방을 만들거나 연결할 필요가 없다. |
| `/lunch` | 기존 주소 호환 | `/`로 리다이렉트한다. 별도 첫 화면을 중복 운영하지 않는다. |
| `/lunch-room/$roomId` | 실시간 추첨방 | 기존 UUID와 초대 주소를 그대로 사용한다. |

상단에는 점메추 홈과 **도구 모음** 진입을 둔다. 번호·복권 도구는 보조 메뉴에서 직접 이동할 수 있게 한다. **혼자 추첨하기**는 메인과 방에서 찾을 수 있는 보조 링크로 제공한다. 메뉴의 현재 위치와 각 화면 제목을 일치시킨다.

`tool` 값은 `number | lotto | pension`만 허용하며 빠지거나 잘못된 값은 `number`로 정규화한다. 도구 전환은 URL에도 반영해서 직접 열기·새로고침·뒤로 가기가 같은 화면을 가리키게 한다. 현재 저장된 설정·기록의 키와 데이터 형식은 경로 변경으로 초기화하지 않는다.

## 메인: 바로 방 만들기

메인은 별도의 시작 모달 없이 방 생성 폼을 보여준다.

1. 방 이름은 기존 기본값을 채워 두고 수정할 수 있게 한다.
2. 닉네임은 이 브라우저에 저장된 이름을 사용한다. 없으면 임시 닉네임을 만든다. 입력칸을 눈에 띄게 제공하고 수정은 선택 사항으로 둔다.
3. 선정릉 엑셀에서 제공받은 기본 후보 35곳과 출처를 안내한다. 방에 들어간 뒤 방장이 후보를 조정할 수 있다.
4. **방 만들고 입장하기**를 누르면 한 번만 생성 요청하고, 생성한 `/lunch-room/$roomId`로 이동한다.
5. 실패하면 입력을 유지한 채 폼 근처에 오류와 재시도를 제공한다.

처음부터 이름을 정해야 입장할 수 있는 절차는 추가하지 않는다. 방 생성 중 중복 제출은 막으며, 성공한 방의 방장 증명은 이동 전에 이 브라우저에 저장한다. 저장이 제한된 환경에서는 현재 메모리로 이동할 수 있어도 브라우저를 닫은 뒤 권한 복원이 보장되지 않는다는 기존 동작을 유지한다.

샘플의 거리는 제공 엑셀 기준이며 현재 기기 위치에서 구한 값으로 표시하지 않는다. 원본에 없는 대표 메뉴·평점·영업 여부도 만들어 넣지 않는다.

## 방 화면: 추첨 영역과 채팅을 함께 사용

### 넓은 화면

왼쪽은 주 콘텐츠, 오른쪽은 채팅으로 배치한다.

```text
상단 탐색
방 이름 · 연결 상태 · 내 닉네임 변경 · 참가 인원 · 초대 링크
┌────────────────────────────┬──────────────────┐
│ 룰렛 | 결과 보기 전환      │ 채팅             │
│                            │                  │
│ 선택한 보기의 주 콘텐츠    │ 메시지 내부 스크롤│
│                            │                  │
├────────────────────────────┤                  │
│ 추첨 후보 — 항상 표시      │                  │
│ 방장: 선택·적용            │                  │
│ 참가자: 같은 목록 읽기     │                  │
└────────────────────────────┴──────────────────┘
```

- 왼쪽의 **룰렛 / 결과**는 같은 회차를 보는 방식만 바꾼다. 보기 전환은 재추첨·타이머 초기화·서버 명령을 발생시키지 않는다. 결과 보기에는 완료한 현재 결과와 최근 기록을 제공하고 진행 중인 결과는 완료 시점에 공개한다.
- **추첨 후보는 탭이 아니다.** 룰렛·결과 중 어느 보기를 선택해도 그 아래에 별도 섹션으로 남는다. 참가자에게도 현재 선택 후보와 총 개수를 보여준다.
- 방장만 대기 상태에서 후보를 편집·적용한다. 후보는 2곳 이상이어야 하며 서버가 적용을 확인한 다음 새 버전을 사용한다. 난수 요청·회전 중에는 후보 변경과 중복 시작을 막는다.
- 다음 회차의 후보를 바꿔도 이전 결과는 당시 후보의 이름·순서·분류를 담은 스냅샷을 사용한다.
- 오른쪽 채팅은 데스크톱에서 화면 안에 붙어 있도록 하고, 긴 메시지 목록은 채팅 안에서 스크롤한다. 입력칸과 보내기 버튼은 접근 가능한 위치를 유지한다. 과거 메시지를 읽는 중에는 새 메시지로 스크롤을 강제로 이동하지 않는다.
- **페이지와 왼쪽 콘텐츠의 세로 스크롤을 허용한다.** 전체 페이지를 무조건 화면 높이에 고정하지 않으며, 후보를 숨기거나 지나치게 줄여서 바깥 스크롤을 없애지 않는다. 채팅의 내부 스크롤과 페이지 스크롤 역할을 구분한다.

### 좁은 화면과 확대

읽는 순서는 방 정보 → 룰렛/결과 → 후보 → 채팅이다. 후보는 좁은 화면에서도 별도 탭에 숨기지 않는다. 데스크톱의 채팅 고정은 공간이 부족하면 풀고, 세로 흐름으로 제공한다. 320px 너비와 확대 상태에서 가로 스크롤 없이 주요 행동과 채팅 입력을 사용할 수 있어야 한다.

닉네임과 변경 행동은 방 상단에서 찾을 수 있게 한다. 참가자 목록 안을 먼저 열어야 이름을 바꿀 수 있는 구조를 없앤다. 입력값은 최대 20자, 빈 이름은 허용하지 않으며 변경 후 다른 참가자에게도 반영한다.

룰렛·결과 보기 전환은 키보드로 조작하고 선택 상태를 알 수 있게 한다. 감소 모션, 결과의 텍스트 표현, 복사 실패 시 수동 복사, 연결 상태와 오류 안내는 유지한다. 초대 링크·결과·각 기록 복사도 유지한다.

## 입장·권한·수명 정책

초대 주소를 열면 저장된 닉네임 또는 임시 닉네임으로 자동 입장한다. 같은 브라우저에 해당 방의 방장 증명이 있으면 서버 확인 후 방장으로 복원한다. 닉네임이 같거나 먼저 입장했다는 이유로 방장 권한을 주지 않는다.

방의 만료 시각은 **생성 시각 + 24시간**으로 고정한다. 새 입장, 채팅, 추첨, 방장 복귀로 연장하지 않는다. 방장이나 전원이 나갔다고 즉시 삭제하지 않는다. 휴면과 재접속은 유효한 방의 상태를 복원하는 동작이다.

| 상황 | 서버와 권한 | 화면과 복귀 |
| --- | --- | --- |
| 대기·추첨 진행 | 방장이 시작하고 서버가 회차·후보·결과·타임라인을 확정한다. | 모두 같은 회차를 시청한다. 늦게 입장하면 경과 시점에 맞춰 복원한다. |
| 방장만 이탈 | 만료 시각을 유지하고 방장을 자동 이전하지 않는다. | 방장 오프라인을 표시한다. 참가자는 채팅할 수 있고 새 추첨·후보 편집은 기다린다. |
| 전원 이탈 | 방 데이터와 원래 만료 시각을 보관한다. 연결이 없으면 휴면할 수 있다. | 24시간 안에 같은 링크로 돌아오면 복원한다. 방장은 기존 증명이 필요하다. |
| 일시적인 연결 끊김 | 같은 방으로 재연결하며 별도 추첨을 만들지 않는다. | 다시 연결 중임을 표시하고 조작을 제한한다. 회차·채팅·기록을 다시 받는다. |
| 생성 후 24시간 경과 | 서버가 방 데이터·채팅·결과·방장 해시와 alarm을 삭제한다. | 이용 종료와 **새 방 만들기**를 제공한다. 이전 UUID를 되살리지 않는다. |
| 없거나 복원할 수 없는 방 | 옛 링크나 없어진 방을 같은 ID로 새로 생성하지 않는다. | 방을 찾을 수 없다는 안내와 새 방을 만드는 경로를 제공한다. |

방장 증명은 참가 링크나 공유 스냅샷에 넣지 않고 서버에는 해시만 저장한다. 같은 브라우저의 저장소를 삭제했거나 다른 브라우저로 옮기면 기존 방장 권한을 복원할 수 없다. 이번 범위에는 계정 로그인·증명 이전·자동 방장 승계가 없다. 기존 `?guest=1`은 방장 증명을 보내지 않고 참가자로 확인하는 동작을 유지한다.

동시 참가자는 최대 30명, 채팅은 최근 100개와 메시지당 500자·750ms 전송 간격, 완료 추첨 기록은 최근 20회다. 방 기록은 서버에, `/solo`의 개인 기록은 브라우저에 남는 별개 데이터다. 만료한 방의 기록을 개인 기록으로 자동 복사하지 않는다.

만료·없는 방·권한 복원 실패는 일시적인 통신 오류와 구분한다. 계속 재연결만 반복하지 않고 새 방 생성 경로를 제공하며, 새로 생성하면 새 UUID와 새로운 24시간이 시작된다. 이전 방의 사람·채팅·결과가 복구됐다고 표현하지 않는다.

## 구현 순서와 완료 기준

| 단계 | 변경 | 완료 기준 |
| --- | --- | --- |
| 1. 경로·탐색·브랜드 | `/` 메인, `/tools`의 URL별 도구, `/solo`, `/lunch` 리다이렉트, 공통 탐색·제목·설명 | 모든 새 경로를 직접 열고 새로고침할 수 있다. 기존 방 URL이 그대로 연결된다. 세 번호 도구의 기존 기능·설정·기록을 유지한다. |
| 2. 인라인 방 생성 | 현재 생성 요청과 저장 동작을 재사용하는 메인 폼 | 메인에서 추가 모달 없이 생성·입장한다. 저장 이름/임시 이름을 수정할 수 있다. 중복 제출·후보 부족·서버 실패에서 잘못된 방을 만들지 않는다. |
| 3. 방 화면 재배치 | 왼쪽 룰렛/결과 보기, 그 아래 상시 후보, 오른쪽 채팅, 상단 닉네임 변경 | 방장·참가자 모두 같은 후보를 본다. 편집 권한은 서버가 유지한다. 보기 전환 중에도 진행 회차가 바뀌지 않는다. 페이지 스크롤과 채팅 내부 스크롤이 함께 동작한다. |
| 4. 종료·복귀 흐름 | 방장 이탈·전원 이탈·재접속·24시간 만료·새 방 생성 안내 정리 | 이탈만으로 방을 삭제하거나 승계하지 않는다. 원래 만료 시각이 유지된다. 만료 데이터는 삭제되고 예전 링크에서 새 방으로 이동할 수 있다. |
| 5. 통합 확인 | 기존 테스트 조정, 새 경로·화면·수명 회귀 검사, 실제 브라우저 확인 | 전체 테스트·타입 검사·변경 파일 검사·배포용 빌드를 통과한다. PC 두 브라우저와 320px·감소 모션에서 핵심 흐름을 확인한다. |

브라우저 확인은 메인 생성 → 다른 브라우저 초대 → 채팅 → 후보 적용 → 공동 추첨 → 룰렛/결과 전환 → 기록 복사 → 진행 중 재접속까지 이어서 수행한다. 서버 시간 제어 테스트로 고정 만료, 전원 이탈 후 유지, 영구 삭제와 중복 추첨 방지를 확인한다. 실제로 24시간을 기다리는 방식으로 검증하지 않는다.

## 후속 계획에만 포함할 항목

다음 항목은 후속 GitHub 이슈에서 조건과 완료 기준을 정한다. 이번 화면에 작동하지 않는 선택지나 완료한 기능으로 표시하지 않는다.

- **공개방·비공개방 — [후속 이슈 #3](https://github.com/acee90/random-number-generator/issues/3):** 공개 목록 노출 여부와 링크를 아는 사람만 입장하는 방식, 인증을 요구하는 비공개방 정책은 아직 미정이다. 검색 목록에 보이지 않는 것과 입장 권한 검증은 별개로 설계한다. 현재 방은 목록 없이 링크로 참여하는 방식이다.
- **커스텀 메뉴와 엑셀 — [메뉴·권한 후속 이슈 #4](https://github.com/acee90/random-number-generator/issues/4):** 개별 추가·수정·삭제, 목록 저장, `.xlsx` 내보내기·가져오기와 전체 교체 미리보기다. 검증 전 기존 목록을 바꾸지 않고, 적용은 전체 교체로 처리하며 이전 버전 복구를 설계한다. 진행 회차의 스냅샷은 그대로 유지한다.
- **투표·가중치 추첨 — [후속 이슈 #5](https://github.com/acee90/random-number-generator/issues/5):** 투표 집계와 당첨 확률의 관계, 방장 조정 권한, 참가자에게 보이는 확률과 동률 규칙을 먼저 정한다. 현재는 모든 선택 후보가 같은 확률이다.
- **실제 음식점 검색 — [#10](https://github.com/acee90/random-number-generator/issues/10):** 공식 API의 제공 범위·이용 조건을 조사하고 결과에서 후보를 고르는 흐름을 구현한다.
- **엑셀 왕복 편집 — [#9](https://github.com/acee90/random-number-generator/issues/9):** #4의 목록 모델을 기반으로 실제 `.xlsx` 편집·미리보기·교체·복구를 제공한다.
- **추가 연출 — [#11](https://github.com/acee90/random-number-generator/issues/11):** 사다리·오리 경주·핀볼을 같은 확정 결과로 재생하는 후속 계획이다.
- **전체 화면·효과음 — [#12](https://github.com/acee90/random-number-generator/issues/12):** 표시와 소리의 선택 기능을 다룬다.
- **결과 공유 확장 기획 — [#13](https://github.com/acee90/random-number-generator/issues/13):** 이미 구현된 복사 기능 이후의 공유 방식·정보 범위·만료 정책을 정한다.

도메인 운영 연결과 공개 배포도 이 구현 계획과 분리한다. 실제 위치 정보 수집, 로그인, 자동 방장 이전, 방의 영구 보관, 파일·음성 채팅은 이번 IA 전환에 포함하지 않는다.

## 추가 반영: 채팅과 추첨 상세 기록

- 내 채팅은 오른쪽, 다른 참가자의 채팅은 왼쪽 말풍선으로 구분한다. 서버가 보낸 입장·퇴장·이름 변경·추첨 상태 알림은 가운데 시스템 메시지로 표시한다.
- 닉네임은 채팅 헤더의 작은 편집 버튼으로 바꾼다. 평소에는 전체 입력 폼을 차지하지 않는다.
- 추첨 시작은 방장에게만 허용한다. 참가자에게는 비활성 대기 상태를 명확히 표시하며 서버가 최종 권한을 검사한다.
- 추첨 시작 요청 시 후보·각 후보의 균등 확률·참가자 명단·요청 시각을 회차에 고정한다. 결과에는 생성 시각·공통 연출 시각·난수 출처·회차 ID를 함께 보관한다.
- 결과 기록을 펼치면 당시 후보와 확률, 참가자를 확인하고 전체 상세 내용을 복사할 수 있다. 이전 기록에 없는 참가자 정보는 현재 명단으로 채우지 않는다.
- 원시 시드·외부 API 키·난수 원본 바이트를 저장하거나 공유하지 않는다.
- 모바일 채팅은 화면의 남은 높이에 맞춰 메시지 목록만 내부 스크롤하고 입력칸과 전송 버튼은 화면 안에 둔다.
