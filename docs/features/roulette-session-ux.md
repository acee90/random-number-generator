# 룰렛 UI 검토 안내

게임 화면의 기준 문서는 [게임 화면 lifecycle과 로직 점검](game-screen-lifecycle.md)이다. 화면별 기능·방장/참가자 권한·전환 조건·실패 복구·데이터 보존·재현한 문제·최적화와 검증 기준을 함께 정리한다.

기획과 진행 상태는 [#46](https://github.com/acee90/random-number-generator/issues/46), 상위 로드맵은 [#7](https://github.com/acee90/random-number-generator/issues/7)에서 관리한다. 실제 후보 모델·개인 저장은 [#4](https://github.com/acee90/random-number-generator/issues/4), 확률 투표는 [#5](https://github.com/acee90/random-number-generator/issues/5), 파일 교체는 [#9](https://github.com/acee90/random-number-generator/issues/9)에 연결한다.

## 실제 구현 연결

기획 커밋 `c965505` 이후 `feat/room-lifecycle`에서 실제 React 화면과 서버를 연결했다. [기준 문서 0절](game-screen-lifecycle.md#0-실제-구현-상태--2026-11-15-로컬)에 구현 범위와 한도를 정리한다. 로컬 앱은 `npm run dev` 후 <http://127.0.0.1:3000/create>, 역할/단계별 독립 화면은 Storybook의 `PAGES/추첨방`에서 확인한다. 아래 `8766/preview.html`은 보존한 HTML 기획 시안이다.

새 구현은 역사적 F1(제목 적용의 추천 소실)·F2(이름 변경의 제외 해제)·F4(옵션 적용의 암묵 결과 종료)를 서버/React 회귀로 방지한다. HTML 시안의 감사 JSON을 해결 완료로 덮어쓰지 않는다. Ready와 추첨 전 확률 투표는 아직 도입하지 않았다. 이후 사용자 검토로 새 방 편집 시작·준비 단계 밖 편집 잠금·후보/옵션 조회 분리와 준비 페이지 내 직접 편집을 추가했다. 원격 푸시·운영 배포는 별도다.

## 최신 UI 흐름

- 최초 생성: **편집 → 마감 → 룰렛 대기**. 대기의 **후보 편집**으로 필요할 때만 다시 준비한다.
- 기본 반복 게임: **대기 → 룰렛 돌리기 → 추첨 → 결과 → 다음 게임 대기 화면으로 → 대기**.
- 후보 추천: **후보 추천받기 → 접수 중**. 방장은 **접수 종료 / 마감**을 선택한다.
- 접수 종료 후에는 목록에 머물며 **다시 접수받기 / 마감**을 제공한다.
- 마감은 접수 중과 접수 종료 후 어디서든 즉시 대기로 이동한다. 자동 투표 단계나 자동 추첨을 끼워 넣지 않는다.
- 대기에는 큰 룰렛과 이번 후보 이름 요약을 표시한다. 전체 후보·등록자·확률은 읽기 전용 **후보 보기**에서 확인한다. 후보는 준비 단계 목록에서 직접 편집하고, 방 이름은 우상단 톱니바퀴 **방 설정**에서, 중복 제외는 주화면의 **이번 게임 옵션 / 다음 게임 옵션**에서 따로 변경한다. 방장은 추첨 중을 제외한 게임 사이에 설정을 변경하고 참가자는 조회만 한다. 설정 변경은 후보 초안이나 현재 단계를 바꾸지 않는다.
- 제외 목록은 룰렛 옆에 표시하고, 좁은 화면에서는 아래로 배치한다. 현재 당첨을 포함한 누적 내역과 개수를 일치시킨다. 결과 화면에서는 OFF로 바꿔도 다음 게임 전까지 목록을 유지한다. 후보 필터의 직접 제외와 구분한다.

후보 추천용 ON/OFF 스위치, 영구 등록 허용과 별도 모집 진입의 이중 조작, 결과에서 즉시 재추첨하는 흐름은 사용하지 않는다. 게임 사이의 중복 제외 옵션 ON/OFF는 유지한다.

## 중복 제외와 초기화 확인

- 결과 화면에서 옵션을 ON↔OFF로 바꿔도 기존 자동 제외 ID와 메타데이터는 유지한다. OFF로 다음 게임에 넘어가면 목록을 비운다. OFF 추첨 자체는 당첨을 추가하지 않는다.
- **ON 추첨 성공은 누적, OFF 추첨 성공은 추가하지 않는다.** 결과에서 ON으로 켜면 현재 당첨은 즉시 추가하지만 OFF 다음 게임에서 켜도 과거 당첨은 복원하지 않는다.
- OFF 추첨은 초기화 확인 없이 시작한다. 수동 초기화 확인은 현재 revision으로 검증한다. 이 변경은 [#69](https://github.com/acee90/random-number-generator/issues/69)에서 관리한다.
- 수동 **‘제외 목록 초기화’**도 확인 후 실행하지만 추첨은 시작하지 않는다. 수동 제외·후보 원본·과거 기록·현재 결과는 유지한다.
- 회차 시작 때의 옵션을 고정해 성공 결과와 제외 처리를 한 번만 확정한다. 결과 확정 전 실패는 기존 목록을 유지하고, 결과 재수신은 다시 누적하지 않는다. 대기 복귀는 현재 옵션이 ON이면 유지하고 OFF이면 비운다.
- 연출 중 새 당첨 후보가 목록에 먼저 노출되지 않게 한다. ON 연출은 이전 제외 사본, OFF 연출은 초기화된 빈 목록을 보이고 새 내역은 결과 공개 후 표시한다.

## 시안과 검토 범위

- 로컬 미리보기: <http://127.0.0.1:8766/preview.html>
- 시안 소스: [roulette-session-wireframe.html](../../output/roulette-session-ux/roulette-session-wireframe.html)
- 역할별 화면: **방장 화면 / 참가자 화면을 동시에 표시**한다. 캐러셀 대신 PC에서 좌우 두 패널, 760px 이하에서는 상하로 같은 모의 방의 진행 상태·후보·결과를 비교한다.
- 각 역할 패널 내부가 560px 이하이면 룰렛과 제외 목록도 상하로 배치한다. 개인 다이얼로그는 그 역할 패널만 가리는 미리보기용 overlay와 `show()`로 열어 다른 역할의 작업을 함께 비교한다.
- 접수 종료 화면 안의 확률 투표, Ready 채택·대상·무효화 정책, 정확한 버튼 배치·크기는 검토 중이다.

[로직 감사](game-screen-lifecycle.md#7-실제-재현한-시안의-허점)에서 초안 충돌로 추천 소실, 이름 수정 시 당첨 제외 해제, Ready 조건 변경 누락, 같은 옵션의 경로별 화면 전환 불일치를 재현했다. [감사 결과 JSON](../../output/roulette-session-ux/lifecycle-audit.json)은 새 제외 정책 반영 전 작성한 역사적 재현 자료이며, 새 정책 검증 결과로 덮어쓰지 않는다. 이 재현 자료는 HTML 시안 기준으로 보존한다. 실제 서비스 구현의 해결/검증 상태는 위 실제 구현 연결 절과 #46에서 구분한다.

동시 패널과 역할별 overlay는 비교용 구성이며 실제 서비스의 modal·포커스 트랩을 대체하지 않는다. 시안의 로컬 DOM 확인은 실제 서비스 연결·서버 다중 사용자 동기화·브라우저 네이티브 modal·모바일/키보드 검증·부하 측정·운영 반영과 구분한다. 실제 현행 동작은 [방 운영 설명](../lunch-rooms.md)을 참고한다.
