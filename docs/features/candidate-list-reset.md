# 후보 목록 비우기와 다시 만들기

관련 이슈: [#4](https://github.com/acee90/random-number-generator/issues/4), [#44](https://github.com/acee90/random-number-generator/issues/44). 진행 상태와 후속 범위는 GitHub 이슈에서 관리한다.

현재는 **기존 Storybook 후보 편집기를 보완한 검토 단계**다. 목록 저장·불러오기 흐름과 공통 UI를 재사용하며, 실제 방 API 및 XLSX 파일 읽기는 연결하지 않았다. Storybook 동작을 운영 서비스에 연결한 것으로 보지 않는다. 사용자에게 화면과 흐름을 확인받고 디자인을 확정한 뒤 서비스 연결·검증을 진행한다.

## 목적

정해진 음식점 목록을 하나씩 삭제하지 않고 새 후보 목록을 준비할 수 있게 한다. 편집 중인 초안, 현재 사용하는 목록, 브라우저에 저장한 목록을 구분해 취소나 초기화 때문에 원본이 사라지지 않도록 한다.

## 범위

- **전체 비우기:** 확인 후 초안의 후보만 모두 지운다. 목록 이름과 ID는 유지한다. 저장본을 삭제하거나 현재 적용된 후보를 즉시 바꾸지 않는다.
- **다시 만들기:** 기존의 새로 만들기·템플릿에서 가져오기·엑셀에서 가져오기 선택 화면으로 돌아간다. 편집 내용이 있으면 버릴지 먼저 확인한다.
- 기존 편집기의 이름·분류·포함 여부 수정, 후보 추가·개별 삭제, 템플릿 추가, 가져온 목록 편집, 저장·불러오기를 재사용한다.
- 저장은 로그인 없이 같은 브라우저에서 다시 불러오는 방식이다. 현재 Storybook 저장소는 실제 서비스와 분리된 예제 전용 공간이다.
- 버튼·입력·라벨·확인창은 공통 UI를 사용한다. PC와 모바일에서 동일한 흐름을 제공하고 키보드 포커스와 잠금 상태를 유지한다.

실제 방의 후보 변경 API·서버 동기화, 실제 XLSX 업로드·읽기, 다른 기기 간 목록 공유는 이번 범위에 포함하지 않는다. 엑셀 가져오기는 예제 데이터로 흐름만 보여준다.

## 사용 흐름

### 전체 비우기

1. 현재 목록이나 저장한 목록을 편집한다.
2. **전체 비우기**를 누르면 편집 중인 후보만 지운다는 확인창이 열린다.
3. 돌아가기를 누르면 초안을 그대로 유지한다. 확인하면 후보를 모두 비우고 **후보 추가**로 포커스를 옮긴다.
4. 후보를 직접 추가하거나 템플릿·엑셀 예제에서 가져와 편집한다. 포함된 후보가 최소 2개이고 입력이 유효해야 저장하거나 방에 적용할 수 있다.
5. 편집을 취소하면 변경을 버릴지 확인하고 현재 적용된 목록으로 돌아간다. 적용 전에는 저장본과 현재 목록이 바뀌지 않는다.

### 다시 만들기

1. 편집기에서 **다시 만들기**를 누른다. 개인 저장 목록이 한도에 도달했다면 편집 화면에서 오류를 알리고 초안을 유지한다.
2. 초안에 변경이 있으면 폐기를 확인한다. 돌아가면 편집을 계속할 수 있다.
3. 확인하면 기존의 세 가지 준비 방법을 보여준다.
   - **새로 만들기:** 빈 후보부터 직접 입력한다.
   - **템플릿에서 가져오기:** 준비된 목록을 복사한 뒤 같은 편집기에서 수정한다.
   - **엑셀에서 가져오기:** 예제 미리보기를 거쳐 같은 편집기에서 수정한다.
4. 새 목록도 저장·적용 전에는 기존 목록에 영향을 주지 않는다. 기존 저장본은 별도 삭제 동작으로만 제거한다.

### 방 생성 후 수정 예제

방장은 대기 상태에서 후보를 편집한다. 추첨·투표·재연결 중에는 변경을 잠그며 초안은 유지한다. **방에 적용**을 누른 뒤 모의 승인 응답을 받기 전까지 공유된 후보를 바꾸지 않는다. 실패하면 초안을 유지해 재시도할 수 있다.

방 후보 적용과 **내 목록에 저장**은 별개다. 방에 적용해도 가져온 개인 저장본을 덮어쓰지 않으며, 사용자가 저장을 누르면 별도 사본으로 보관한다. 이전 회차 기록의 후보와 투표는 새 목록으로 바뀌지 않는다. 이 동작은 Storybook 안의 예제 상태로 검토한다.

## 완료 기준

- 전체 비우기는 확인해야 실행되며 이름·ID·현재 적용 목록·저장본을 보존한다. 비운 뒤 후보 추가로 포커스가 이동한다.
- 다시 만들기의 취소는 초안을 보존하고, 확인은 기존 세 가지 준비 경로로 연결된다. 준비 화면과 편집기를 중복 구현하지 않는다.
- 개인 저장 한도 때문에 다시 만들 수 없을 때 초안을 버리지 않는다. 기존 저장본을 수정해 저장하는 동작은 유지한다.
- 후보가 없거나 입력이 잘못되면 저장·적용을 막고 수정할 위치를 안내한다. 같은 이름의 후보를 자동으로 합치지 않는다.
- 적용 중이거나 편집이 잠겼을 때 전체 비우기·다시 만들기를 실행할 수 없다. 확인창이 열린 뒤 잠겨도 실행을 막는다.
- 방 예제는 승인 전 공유 목록 유지, 실패 후 초안 보존, 명시적 사본 저장, 이전 회차 기록 보존을 확인할 수 있다.
- PC·모바일에서 버튼과 입력을 사용할 수 있고, 확인창 취소·완료 후 키보드 포커스가 사라지지 않는다.
- 관련 자동 검증과 Storybook 화면 검토를 거쳐 사용자 확인을 받는다. 실제 서비스 연결 완료와 운영 배포 완료는 이후 관련 이슈에 따로 기록한다.

## 미결정 사항

- 실제 서비스의 어느 후보 관리 화면에서 이 편집 흐름을 여는지, 방 생성 전·후에 어떻게 이어지는지.
- 실제 방 API의 후보 데이터·버전·권한 검증, 요청 한도와 기존 방 데이터 호환 방식. 현재 예제의 편집·저장 한도는 서비스 계약 확정과 별도로 검토한다.
- XLSX의 시트·열 선택, 지원 형식, 누락·초과 행·파일 오류를 보여주고 고치는 방법.
- 실제 서비스의 브라우저 저장 키·데이터 버전·이관 방식. 예제 저장소를 운영 저장소로 그대로 사용하지 않는다.

미결정 사항은 사용자 화면 확인 후 관련 이슈에서 범위와 완료 기준을 확정한다.
