[597px 화면](../output/entry-card-polish/entry-597.jpg), [긴 제목](../output/entry-card-polish/entry-long-title-320.jpg). 실제 스크린리더·200% 확대·RTL은 이번 확인에 포함하지 않았다. 로컬 미커밋·미푸시·미배포이며 [입장 #19](https://github.com/acee90/random-number-generator/issues/19), [닉네임 검사 #23](https://github.com/acee90/random-number-generator/issues/23), [lifecycle #46](https://github.com/acee90/random-number-generator/issues/46)에서 상태를 관리한다.

**결과·당첨 제외 내역 후속 보완 — 2026-11-16:** 당첨 이름 강조·투표 집계 공간 확대, 방장의 1회 결과 투표, 차수·시각을 갖춘 당첨 제외 내역을 로컬 구현했다. 전체 47파일·1,398개 테스트와 타입·앱/Storybook 빌드, 로컬 HTTP/WebSocket 33개 흐름 검증을 통과했다. 실제 브라우저에서 방장·참가자 투표와 대기 복귀, 597/320px 배치, 200개 내역의 키보드 스크롤을 확인했다. 로컬 미커밋·미푸시·미배포이며 운영에는 반영하지 않았다. [lifecycle #46](https://github.com/acee90/random-number-generator/issues/46)과 [결과 피드백 #20](https://github.com/acee90/random-number-generator/issues/20)에서 진행 상태를 관리한다. 아래 동작 설명은 이 로컬 변경을 포함하며 이전 검증 기록을 이번 변경의 배포 완료로 해석하지 않는다.

**후보 개수 상한 제거 — 2026-11-22 로컬 구현:** 개인 목록·단독 룰렛·방 편집·참가자 추천의 200개 개수 검사를 제거했다. 797개를 넘는 근처 음식점도 한 번에 추가할 수 있다. 후보 개수 대신 방 생성/편집 요청 256KiB, 개인 목록 전체 8MiB, 방 스냅샷·저장값 8MiB의 바이트 안전장치를 적용한다. 방 스냅샷은 연결 정보와 저장 메타데이터를 위한 여유를 남겨 용량이 큰 후보·추첨 기록 조합을 거절한다. 전체 후보 라벨이 읽기 어려워지는 룰렛은 후보 수와 추첨 동작을 유지하고 텍스트 라벨만 생략한다. 구현·회귀 검사·실제 브라우저 검증은 [#4](https://github.com/acee90/random-number-generator/issues/4)와 [#46](https://github.com/acee90/random-number-generator/issues/46)에서 관리하며, 운영 배포와 구분한다.

홈의 **방 만들기**(`/create`)와 **혼자 추첨하기**(`/solo`)는 같은 두 단계에서 방 이름·닉네임을 입력하고 후보와 필터를 준비한다. 생성하면 두 모드 모두 방장으로 룰렛 대기 화면에 입장한다. 공동방 초대 주소는 `/lunch-room/<UUID>`이며 Durable Object와 WebSocket으로 참가자·채팅·게임을 동기화한다. 개인 방 주소는 `/solo/<UUID>`이며 현재 탭의 `sessionStorage`에서 후보·진행 중인 회차·투표·기록을 복원한다. 개인 방은 탭을 닫거나 생성 후 24시간이 지나면 만료된다. 게임 단계, 결과 투표, 후보 편집, 방 설정과 종료 후 기록 보기는 두 모드가 공유한다. 기존 `/lunch`는 홈으로 이동하며 번호 도구는 `/tools?tool=number|lotto|pension`에서 연다. 검색 색인에는 홈과 `/solo` 진입 화면만 공개한다. [모드 통합 #58](https://github.com/acee90/random-number-generator/issues/58) · [방 만들기 #92](https://github.com/acee90/random-number-generator/issues/92)

현재 기본 목록은 사용자 제공 `회사주변_음식점_목록.xlsx`의 `회사 주변 음식점!A6:C112`에 있는 107곳·11개 분류다. 원본 순서를 유지하며 메뉴는 임의로 추가하지 않는다. 분류 미확인 2곳은 원본의 `확인 불가`를 유지하고 거리 미확인 1곳은 거리 값을 생략한다. 단독 추첨은 이 목록을 사용한다. 방장은 후보 준비 중 **목록 불러오기**에서 기본 목록을 선택할 수 있다. [데이터 갱신 이슈 #17](https://github.com/acee90/random-number-generator/issues/17)에서 관리하며, 사용자 요청에 따라 이번 갱신에서 기존 방 검증·이관은 제외한다.

**초대 링크 복사**로 보낸 주소를 열면 닉네임 설정 → **입장하기** → 룰렛·채팅 순서로 참여한다. 저장된 이름은 입력란에 미리 채우기만 하고 자동 참가하지 않는다. 입장 전에는 WebSocket 연결이나 참가자 등록을 하지 않는다. 방 생성 화면에서 이미 닉네임을 정하고 **방 만들기**를 누른 경우에만 메모리에 30초간 유지하는 일회성 입장 요청으로 중복 입력을 생략한다. 이 요청은 URL·브라우저 저장소에 남기지 않으며 새로고침·새 탭에서는 다시 닉네임을 확인한다. [닉네임 입장·중복 처리 이슈 #19](https://github.com/acee90/random-number-generator/issues/19)에서 관리한다.

입장 카드의 방 제목은 별도 `GET /api/lunch/rooms/<UUID>/entry-info`로 조회한다. 응답은 제목만 담고 인증 증명·참가자·후보를 반환하지 않는다. 이 조회를 위해 WebSocket이나 join을 열지 않으며, 조회 핸들러는 참가·활동·채팅·만료 시각을 갱신하지 않는다. cold wake 때 기존 PartyServer의 일반 복구는 그대로 수행한다. 조회 실패는 일반 방 제목으로 대체하고 기존 닉네임 검사·명시적 입장 조건을 유지한다. 늦은 이전 방 응답과 취소 뒤 응답은 무시한다.

닉네임은 NFKC 정규화와 앞뒤 공백 제거 후 1~12자(UTF-16)이며 제어·숨김 문자는 허용하지 않는다. 같은 방에서 온라인·자리비움 상태인 서로 다른 참가자는 대소문자를 포함해 정규화 기준으로 같은 이름을 쓸 수 없다. 오프라인 이름은 재사용할 수 있고, 복귀할 때 이미 사용 중이면 입력 화면에서 다른 이름으로 재시도한다. 인증된 동일 참가자의 다중 연결은 허용하며 이름만 같다고 신원을 합치거나 방장 권한을 주지 않는다. 서버가 승인한 이름만 표시·저장한다. 명시적인 이름 선택은 `updateName: true`로 보내고 이후 자동 재연결은 서버의 최신 이름을 복원한다.

입장 후 이름은 채팅 입력창 근처의 내 프로필에서 바꾼다. 채팅 공간·프로필 편집·참가자 상태 개선은 [GitHub 이슈 #14](https://github.com/acee90/random-number-generator/issues/14), 결과·상세 기록·후보 목록 배치와 닉네임 제한은 [GitHub 이슈 #15](https://github.com/acee90/random-number-generator/issues/15)에서 관리한다.

입장 화면에서는 입력을 350ms 멈추면 닉네임 사용 가능 여부를 자동 확인한다. 한글 조합 중에는 기다리고 확인 중에는 입력창 오른쪽의 스피너를 표시한다. 사용 가능하면 같은 자리에 체크 아이콘을 표시하며, 정상 상태의 설명은 스크린리더용 상태 알림으로 유지한다. 오류와 재확인 버튼은 예약된 공간에 표시한다. 확인·중복·오류 상태에서는 입장을 막고 사용 가능 상태에서만 제출한다. 입력 변경 시 이전 요청을 취소하고 늦은 응답을 무시한다. 확인 요청은 같은 출처의 `POST /api/lunch/rooms/<UUID>/nickname-availability`로 보내며 참가자 등록·채팅·활동·만료 시각을 바꾸지 않는다. 본인 제외를 위한 비공개 증명은 요청 본문에만 넣고 응답에는 정규화된 이름과 가능 여부만 담는다. 확인 직후 다른 참가자가 먼저 입장할 수도 있으므로 실제 입장에서 중복을 다시 검사한다. 관련 진행은 [자동 중복 확인 이슈 #23](https://github.com/acee90/random-number-generator/issues/23)에서 관리한다.

입장·채팅의 렌더 비용은 [성능 개선 이슈 #25](https://github.com/acee90/random-number-generator/issues/25)에서 관리한다. 정적인 룰렛 SVG와 후보 목록은 실제 표시 내용이 같으면 재사용하고, 회전·버튼·권한·체크 상태와 최신 콜백은 계속 갱신한다. 첫 입장 화면에는 서버가 승인한 선택 목록을 바로 표시한다. 개발용 Profiler의 계산 횟수와 실제 네트워크 대기는 구분한다. 이 개선은 닉네임 확인을 생략하거나 서버의 중복·권한 검사를 우회하지 않는다.

## 화면 배치와 게임 단계

같은 방 URL과 연결을 유지하면서 공유 단계에 따라 왼쪽 주화면을 바꾼다. 데스크톱 오른쪽 채팅과 참가자·지난 기록은 계속 사용할 수 있다. 좁은 화면에서는 게임과 채팅을 위아래로 배치하고, 룰렛 옆의 제외 목록은 아래로 내려 룰렛 크기를 유지한다. 룰렛/결과 전환 탭과 모든 단계에 상시 펼친 후보 편집 목록은 사용하지 않는다. `/solo`의 개인 기록과 방의 공동 기록은 별개다.

| 공유 단계 | 주화면과 가능한 작업 |
| --- | --- |
| 최초 편집·편집 재진입 `editing` | 후보 수에 관계없이 **검색 · 필터 · +**가 있는 공통 편집기로 시작. 목록과 추첨 포함 범위를 정리한 뒤 **후보 추천받기 / 마감**. 참가자는 조회·방장 준비 대기, 추천은 접수가 열린 뒤 가능 |
| 대기 `waiting` | 큰 룰렛과 중복 제외 스위치를 통합한 제외 목록. 방장은 **후보 편집 / 룰렛 돌리기**. 후보 목록은 본문에 반복하지 않고 상단 **후보 보기** 팝업에서 조회. **후보 보기 / 옵션 보기**는 읽기 전용이며 후보·게임 필터 변경과 추천 접수는 후보 편집으로 복귀. 방 이름은 독립된 우상단 **방 설정**에서 변경 |
| 추천 접수 `collecting` | 후보·등록자 목록과 추천 입력. 방장과 참가자는 후보를 추가하고, 참가자는 자기 추천만 삭제. 방장은 **추천 스위치 OFF로 접수 종료 / 마감** |
| 접수 종료 `reviewing` | 같은 목록에 머물며 참가자 추가·삭제를 잠금. 방장은 최종 정리 후 **추천 스위치 ON으로 재개 / 마감** |
| 추첨 준비 `fetching`·진행 `drawing` | 현재 룰렛에서 요청 대기·공통 연출. 후보·옵션·접수 전환·추가 시작을 잠그고 조회와 채팅 유지 |
| 결과 `result` | 큰 당첨 이름·분류와 넓은 좋아요/싫어요 피드백·집계. 방장도 당시 명단에 있으면 1회 투표. 방장이 **다음 게임 대기 화면으로**를 눌러야 기록 보관과 대기 복귀하며 본인 표 처리 중에는 이동 잠금 |
| 종료 `closed` | 기존 참가자의 기록 조회·TXT 내보내기와 새 추첨 경로. 공유 상태 변경 불가 |

후보 없이 시작한 방도 공통 편집기를 바로 연다. 목록 하단의 **+ 추가하기**를 누르면 같은 행에서 후보 이름을 입력할 수 있다. **Enter**나 **추가**로 등록하고 **Esc**로 입력을 접는다. **+** 메뉴에는 여러 개 추가와 목록·주변 음식점 가져오기가 있다. 후보를 준비하고 **마감**하면 룰렛 대기로 이동한다. 이후 같은 목록을 반복할 때 편집 단계를 다시 강제하지 않는다. **후보 추천받기 스위치 OFF**는 추천 입력만 닫고 목록에 머문다. **마감**은 접수 중이든 종료 후든 즉시 대기로 이동한다. 스위치를 먼저 끄거나 별도 확률 투표 화면을 거칠 필요가 없으며, 마감만으로 룰렛을 돌리지 않는다. 다시 접수받으면 기존 후보·제외 내역을 유지하면서 새 접수 ID를 발급하고, 이전 접수의 늦은 추천은 거절한다. 보내지 않은 입력은 개인 초안으로 남기며 접수 재개 때 자동 등록하지 않는다.

결과에서 직접 다음 추첨을 시작하거나 자동으로 대기로 넘어가지 않는다. **결과 → 명시 대기 복귀 → 별도 추첨 시작**을 서버에서도 검사한다. 같은 후보로 반복할 때 추천 접수·마감을 매번 요구하지 않는다.

### 후보·옵션과 편집 초안

상단 **후보 보기** 팝업은 전체 후보·이번 추첨 포함 수·등록자·분류/후보 필터/당첨 제외 사유·확률을, **옵션 보기**는 적용 조건을 읽기 전용으로 보여준다. 개별 필터 제외는 **후보 필터에서 제외**로 표시하며 당첨 제외 패널에 별도 ‘직접 제외’ 목록을 만들지 않는다. 방장도 대기에서 목록과 게임 필터를 바로 수정하지 않는다. **후보 편집**을 눌러 준비 단계로 돌아가면 상단에서 후보 이름을 검색하거나 **필터**에서 분류를 고른다. 각 행의 체크박스는 개별 추첨 포함을 설정한다. 이름을 누르면 바로 편집할 수 있고 행의 **⋯**에서 이름 수정, 분류 변경, 삭제를 할 수 있다. 후보 원본은 한 벌이며 별도 편집 팝업을 열지 않는다. 후보와 필터를 바꾸는 요청은 준비 단계에서만 허용한다. 결과는 명시 대기 복귀 후 후보 편집에 진입한다. 대기 본문의 이번 후보 목록은 생략하며, **후보 추천받기**도 편집 화면에서만 제공한다.

**목록 불러오기**는 빈 화면/편집기를 유지한 개인 다이얼로그다. 실제 기본 107곳 또는 같은 브라우저의 개인 저장본을 새 ID·전체 포함 상태의 사본으로 가져온다. 기존 후보가 있으면 교체 확인을 받고, 취소·Escape는 기존 초안을 유지한다. 가져오기는 개인 초안을 채우며 서버 적용은 **마감 / 접수 전환**의 저장 승인과 구분한다.

**내 목록에 저장**은 방 적용과 별개로 이름을 붙여 개인 사본을 만든다. 서비스 키 `jeommechu:candidate-lists:v1`에 최대 20개를 같은 브라우저·같은 주소에 보관하며 후보 개수는 제한하지 않는다. 브라우저 저장량을 위해 모든 개인 목록의 직렬화 크기는 8MiB로 제한한다. 불러오기 창의 **저장 목록 삭제**는 확인 후 해당 개인 사본만 지우며 현재 방·초안·다른 저장본은 유지한다. 읽기·쓰기·삭제 실패는 기존 내용을 보존하고 재시도를 안내한다. Storybook 전용 저장소와 분리하며 다른 기기·주소나 브라우저 데이터 삭제 뒤에는 자동 복원하지 않는다. 실제 XLSX와 홈/solo 전체 라이브러리 연결은 후속 범위다.

목록 선택 카드에는 후보·분류 수, 앞쪽 후보 3개 미리보기, 저장본의 저장 시각을 표시한다. 최근에 실제로 초안에 불러온 목록에는 표시를 붙이고 저장 목록을 최근 불러온 순으로 정렬한다. 교체 확인을 취소하거나 가져오기가 거절되면 기록하지 않는다. 이 기록은 추첨 참여 시점이 아니라 **불러온 시점**이며, 기능 도입 전의 사용 이력과 기본 목록의 저장일을 만들어내지 않는다. 선택 기록은 별도 키 `jeommechu:candidate-list-usage:v1`에 최근 100개 출처까지만 보관하고, 오류가 나도 저장 목록 원본이나 불러오기 성공을 취소하지 않는다. 진행 상태는 [후보 목록 #4](https://github.com/acee90/random-number-generator/issues/4)에서 관리하며 아직 로컬 구현·검증 상태다.

우상단 톱니바퀴 **방 설정**은 후보와 독립된 팝업이다. 방 설정은 방 이름 변경과 명시적 방 종료를 다룬다. 후보 편집 화면에는 중복 제외 옵션을 표시하지 않는다. 대기·결과의 **제외 목록 안 스위치**에서만 제공하며 별도 게임 옵션 블록도 만들지 않는다. 방장은 게임 사이에 변경하고 참가자는 상태만 조회한다. 추첨 준비/진행 및 요청 처리 중에는 변경을 잠근다. 방 이름은 **변경 저장**, 게임 옵션의 중복 제외는 즉시 다음 추첨에 적용되며 후보 초안·포함 목록·제외 내역·현재 결과와 단계를 함께 변경하지 않는다. 다른 방장에게서 방 이름이 바뀌면 입력을 보존하고 최신 이름 확인을 요구한다. 저장 실패·닫기 취소에는 이름 초안을 유지한다.

후보 편집은 개인 초안이며 **마감/접수 전환**의 저장 승인 전에는 공유 목록을 바꾸지 않는다. 후보 목록은 안에서 스크롤하고 **+ 추가하기** 행은 바로 아래에 표시한다. **+** 메뉴에서 여러 개 추가, 가져오기, 개인 목록에 저장, 전체 비우기, 변경 취소를 할 수 있다. 추천 접수 중에는 방장의 단일 추가도 공유 추천으로 등록된다. 개별 삭제는 되돌리기를 제공한다. **변경 취소**나 **최신 후보 불러오기**로 초안을 버릴 때는 확인한다. **마감/접수 전환**은 미적용 변경을 먼저 저장한 뒤 승인 성공 시에만 이동하고, 실패하면 현재 단계와 초안을 보존한다. 원격 추천으로 후보 버전이 바뀌면 오래된 전체 목록 적용을 거절하고 초안을 보존한다. 제목만 바꾸는 적용은 후보를 함께 전송하지 않아 새 추천을 지우지 않는다. 후보 이름을 바꿔도 안정된 ID·등록자·당첨 제외는 유지한다. 게임별 중복 제외 옵션은 즉시 다음 추첨에 반영되는 별도 명령이므로, 편집 초안을 취소해도 이미 승인한 옵션 변경을 되돌리지 않는다.

현재 방 목록은 후보 개수 제한이 없으며 후보 이름은 앞뒤 공백을 제외해 **1~80자(UTF-16)**다. 제어·숨김 문자와 미짝 서로게이트는 거절한다. 분류는 선택 입력으로 최대 24자이며 자유 텍스트와 기존 분류 자동완성을 지원한다. 빈 값은 `미분류`, 기존 기본 목록의 `확인 불가`는 원문을 유지한다. 같은 이름을 자동 병합하지 않는다. 요청은 256KiB, 방 스냅샷과 저장값은 각각 8MiB 바이트 한도를 가지며 연결 정보·저장 메타데이터를 위한 여유 공간을 남긴다. 따라서 후보 수만으로는 막지 않지만 메뉴·긴 이름·누적 추첨 기록이 큰 경우 편집이나 추첨 저장이 거절될 수 있다. 참가자 추천 ID와 소유자는 서버가 부여하고, 삭제 권한은 표시 이름이 아닌 참가자 ID로 확인한다. 자기 후보가 남아 있으면 최근 참가자 명단에서 빠져도 재접속 증명을 보존한다.

생성 화면은 포함 후보와 `startInWaiting: true`를 보내 룰렛 대기 상태로 방을 연다. 기존 API 호출은 후보 준비 상태로 방을 만들며 후보 생략과 샘플 ID 지정을 지원한다. 입장 후에는 임의 후보를 추가하고 목록을 0개까지 편집할 수 있다. **실제 포함 후보 0개면 추첨·마감만 막고**, 접수 종료·재개·후보 추가·제외 복원 경로를 남긴다. **1개면 마지막 후보 확정**으로 확률 100% 회차를 같은 서버 기록·난수 출처·연출 계약으로 저장한다.

### 중복 없이 추첨과 제외 목록

방장은 대기·결과의 제외 패널에서 **중복 없이 추첨 · 뽑힌 후보 제외**를 바꿀 수 있다. 추첨 준비·진행 또는 요청 처리 중에는 잠그며 후보 편집 화면에는 표시하지 않는다. 후보 필터의 개별 제외는 이 옵션과 별개이며 기존 동작을 유지한다.

- ON으로 성공한 추첨은 기존 당첨 제외 목록에 이번 당첨 후보를 누적한다.
- 결과 화면의 ON↔OFF 전환만으로는 누적 제외 내역을 지우지 않는다. 현재 당첨을 포함한 모든 행과 개수를 그대로 유지한다. OFF로 **다음 게임 대기 화면으로** 넘어갈 때 자동 제외 ID·메타데이터를 비운다.
- 결과 화면에서 ON으로 켜면 현재 당첨을 즉시 제외 목록에 추가한다. OFF로 다음 게임에 넘어간 뒤 ON을 켜도 과거 당첨을 다시 넣지 않는다. 회차 원본·지난 기록은 변경하지 않는다.
- OFF 추첨은 초기화 확인 없이 바로 시작하고 당첨을 제외 목록에 추가하지 않는다. 대기에서 OFF로 바꾼 경우 추첨을 시작할 때, 구버전 OFF 대기 저장본은 복구할 때 정리한다. 결과 화면의 내역은 재접속해도 다음 게임 전까지 유지한다. 이 동작 수정은 [#69](https://github.com/acee90/random-number-generator/issues/69)에서 관리한다.
- **제외 목록 초기화**도 별도 확인을 받는다. 제외 ID와 당첨 메타데이터만 비우며 성공 추첨 수·현재 결과·기록·후보 원본·후보 필터를 유지하고 추첨하지 않는다.
- 확인 중 후보·옵션·단계가 바뀌면 오래된 조건 승인을 거절한다. 결과 확정 전 실패는 기존 내역을 유지하고, 성공 결과와 제외 처리는 한 번에 저장한다. 대기 복귀나 재접속으로 다시 반영하지 않는다.

룰렛 옆 패널은 **당첨 제외 내역**과 실제 목록 행 수를 일치시킨다. 결과의 현재 당첨도 목록에 표시한다. OFF로 바꿔도 내역이 남아 있으면 다음 게임 전까지 목록을 유지하고 비워질 시점을 안내한다. 초기화는 스위치 옆 ghost 버튼이며 빈 목록에서는 비활성이다. 당첨 후보·N회차 당첨·시각을 최근 추첨순으로 표시한다. 내역이 많으면 제한된 높이 안에서 스크롤하고 키보드로도 접근할 수 있다. 후보 필터의 개별 제외 사유는 상단 후보 보기에서 확인한다.

연출 중 ON은 이전 내역, OFF는 빈 목록을 보여 새 당첨자가 제외 목록에서 먼저 드러나지 않게 한다. 새 내역은 결과 공개 뒤 표시한다. 이 목록과 당첨 메타데이터는 20개 결과 기록 한도와 독립적으로 유지한다. 각 시각은 공통 결과 공개 시각을 기준으로 기록한다.

`drawCount`는 성공한 추첨 수이며 회차의 `roundNumber`와 함께 저장한다. `exclusionRecords`는 현재 제외 후보별 회차 ID·차수·당첨 시각을 보관한다. ON 성공은 누적하고 OFF 성공은 추가하지 않는다. 내역을 비우는 시점은 OFF 대기 복귀/추첨 시작이며 옵션 변경 자체는 현재 결과를 바꾸지 않는다. OFF 성공이나 수동 초기화로 성공 추첨 수를 리셋하지 않으며 다음 차수는 이어진다. 난수·결과 저장 실패에서는 기존 수와 내역을 함께 복원한다.

이전 저장본은 남은 고유 회차와 알려진 차수로만 보완한다. 20개 보관 한도로 과거 회차가 잘렸고 정확한 누적 수를 알 수 없다면 `drawCountIsExact=false`·`roundNumberIsExact=false`로 구분하고 **기록 N번째**와 남은 기록 기준이라는 안내를 표시한다. 차수를 알 수 없으면 **이전 추첨**, 당첨 시각도 찾을 수 없으면 **시각 정보 없음**으로 두며 현재 시각으로 채우지 않는다. 제외 ID가 기준이므로 오래된 기록이 없다는 이유로 제외 후보를 빼거나, 초기화 뒤 기록에서 후보를 다시 넣지 않는다.

## 동작과 보관 범위

- 방장만 전체 후보·옵션·공유 단계를 관리하고 추첨을 시작한다. 참가자는 접수 중 추천·확인 후 자기 추천 삭제, 채팅과 공동 시청을 할 수 있다.
- 서버가 후보 목록·회차 ID·난수 결과·시작 시각·회전각을 한 번 결정한다. 새 추첨의 회전 시간은 4초이며, 브라우저는 회차에 저장된 시간을 경과 시점에 맞춰 재생한다. 기존 7.2초 회차도 시간을 바꾸지 않고 읽는다. 연결과 기기 차이에 따른 프레임 단위 차이는 있을 수 있다.
- 당첨 후보는 기존 난수 결과로 정하고, 연출용 정지 위치만 별도로 무작위 생성한다. `landingFraction`은 당첨 칸 내부 10~90% 사이의 위치이며 서버가 회차별로 한 번 저장해 모든 참가자·늦은 입장·재접속·지난 기록에 동일하게 전달한다. 후보 확률과 당첨 순서는 바꾸지 않는다. 이 필드가 없는 이전 회차는 중앙 정지로 해석한다. 단독 추첨도 같은 범위의 정지 위치를 사용한다. 진행 상태는 [lifecycle #46](https://github.com/acee90/random-number-generator/issues/46)에서 관리하며 이 후속 변경은 로컬 검증 상태다.
- 진행 중 입장하거나 재접속하면 같은 회차와 타임라인을 복원한다. 완료한 현재 결과는 방장이 **다음 게임 대기 화면으로**를 누를 때 투표와 함께 확정 기록으로 보관하고 모두 다음 추첨을 준비한다. 단독 추첨의 브라우저 기록과는 별개다.
- 방장이 접속해 룰렛 대기 상태에 들어가면 서버에서 ANU → Random.org → Web Crypto 순서로 시드를 미리 요청한다. 저장한 값은 5분이 지나면 교체하며 각 회차는 별도의 값을 소비한다. 준비된 값이 없으면 서버 Web Crypto로 바로 추첨한다. 결과에는 실제 사용한 출처를 표시한다. [#92](https://github.com/acee90/random-number-generator/issues/92)
- 최대 30명, 메시지 500자·750ms 전송 간격, 최근 채팅 100개·확정 결과 20개와 현재 회차를 보관한다.
- 방의 만료 시각은 **생성 시각 + 24시간**으로 고정한다. 입장·채팅·추첨·방장 복귀로 연장하지 않는다. 방장이나 전원이 나가도 즉시 삭제하지 않으며, 남은 시간 안에 같은 링크로 복귀할 수 있다.
- 방장 권한은 브라우저에 보관한 별도 토큰으로 확인한다. 서버에는 SHA-256 해시만 저장하며 참가 링크·공유 상태에는 토큰을 넣지 않는다. 동일 브라우저에 증명이 남아 있으면 재접속 시 서버가 확인하고 권한을 복원한다. 방장 브라우저의 저장소를 지우거나 다른 브라우저로 옮기면 증명 없이 권한을 복원할 수 없다.
- 방장이 나갔다고 참가자에게 권한을 자동 이전하지 않는다. 참가자는 채팅하며 기다릴 수 있고, 새 추첨과 후보 변경은 방장이 돌아온 뒤 가능하다. 닉네임이나 입장 순서로 방장을 정하지 않는다. 계정 로그인·권한 이전은 이번 범위에 포함하지 않는다.
- 초대 링크는 옵션 없는 일반 방 주소를 공유한다. 기존 `?guest=1` 주소로 들어와도 브라우저에 유효한 방장 증명이 있으면 서버에 확인해 방장으로 복귀한다. 증명이 없으면 참가자로 입장한다. URL의 옵션이나 닉네임만으로 권한을 부여하지 않는다. 관련 수정: [방장 복귀 버그 #18](https://github.com/acee90/random-number-generator/issues/18).
- 링크를 아는 사람은 참가할 수 있다. 채팅은 텍스트로 표시하며 파일 업로드·개인 메시지는 지원하지 않는다.

## 방의 수명과 복귀

| 상황 | 유지되는 것과 처리 | 화면 안내 |
| --- | --- | --- |
| 방장이 나감 | 원래 만료 시각·후보·채팅·결과를 유지한다. 자동 승계는 없다. | 방장 오프라인, 참가자는 채팅하며 대기 |
| 모두 나감 | 생성 후 24시간까지 보관한다. Durable Object의 휴면은 삭제가 아니다. | 만료 전 같은 링크로 재입장 가능 |
| 일시적인 연결 끊김 | 같은 회차·후보·타임라인·기록으로 재연결한다. | 다시 연결 중, 연결 전 조작 제한 |
| 생성 후 24시간 경과 | 서버가 저장한 방 데이터·채팅·결과·방장 해시와 alarm을 삭제하고 연결을 종료한다. | 이용 종료, 새 방 만들기로 복귀 |
| 없거나 이미 삭제된 방 | 이전 UUID를 다시 생성하거나 기록을 복원하지 않는다. | 방을 찾을 수 없음, 새 방 만들기로 복귀 |

만료는 서버가 판단하며, 브라우저 화면을 닫거나 개인 저장소를 지우는 것과 별개다. 재입장해도 만료 시각은 바뀌지 않는다. 만료 후에는 기존 링크를 재사용해 새 방을 되살리지 않고, 새 방 생성으로 새 UUID와 새로운 24시간을 시작한다. 방 정보가 삭제된 뒤에는 예전 링크에서 ‘만료’와 ‘없음’을 구분하지 못할 수 있으므로 두 경우 모두 새 방 생성으로 안내한다.

현재 서버는 만료 데이터를 삭제하고 클라이언트는 종료 안내와 자동 재연결 중단을 처리한다. 종료·없는 방·권한 복원 실패에서 **새 방 만들기**로 이어지는 화면은 이번 정보 구조 전환의 완료 기준에 포함한다. 별도의 영구 기록 보관이나 자동 방장 승계는 추가하지 않는다.

## 채팅과 회차별 상세 기록

새 닉네임은 방 생성·입장·변경·브라우저 저장·서버 검증 모두 최대 12자로 제한한다. HTML `maxLength`와 같은 UTF-16 길이 기준이며 보조 평면 이모지는 두 단위로 센다. 기존의 긴 현재 이름은 이모지를 반으로 자르지 않고 12자 안으로 이관한다. 과거 채팅과 회차에 기록된 이름은 원문을 보존한다.

내가 보낸 메시지는 오른쪽, 다른 참가자의 메시지는 왼쪽에 표시한다. 연속된 같은 사람의 같은 분 대화는 이름과 시각 중복을 줄이고 시스템 알림에서 묶음을 나눈다. 닉네임 편집과 참가자 목록은 대화를 밀지 않는 작은 창으로 연다. 전송 버튼은 입력창 옆에 두며 Enter 전송·Shift+Enter 줄바꿈과 한글 조합 입력을 유지한다. 입장·퇴장·이름 변경·추첨 시작/완료/실패는 서버가 만든 시스템 메시지로 채팅과 같은 최근 100개 한도 안에 보관한다. 연결을 잃은 브라우저에는 자체 연결 끊김/복구 안내도 표시한다. 시스템 알림을 클라이언트가 임의로 만들어 다른 참가자에게 보낼 수는 없다.

### 참가자 접속 상태

- 초록 점과 **온라인**은 연결되어 있고 최근 5분 안에 활동한 사람, 노랑 점과 **자리비움**은 연결은 있지만 5분 이상 활동이 없는 사람, 빨강 점과 **오프라인**은 마지막 연결이 종료된 사람이다. 색과 상태 이름을 함께 제공한다.
- 서버 시각을 기준으로 판단한다. 키보드·포인터 이동/누름·직접 스크롤 같은 활동을 최대 15초 간격으로 전달하므로 마지막 활동 시각에 그 정도 차이가 있을 수 있다. 브라우저가 오래 멈춰 마지막 입력 이후 30초 넘게 지연된 대기 활동은 보내지 않는다. 연결 유지 ping, 메시지 도착에 따른 자동 스크롤, 단순한 탭 표시 변경은 활동으로 보내지 않는다. 연결 장애는 서버가 종료를 감지한 뒤 오프라인으로 바뀐다.
- 같은 참가자의 연결이 여러 개면 하나라도 최근 활동한 연결이 있는 동안 온라인이다. 방의 현재 참가자 수·추첨 당시 명단에는 연결된 사람만 포함하고 자리비움도 연결 인원으로 센다.
- 최근 참가자 명단은 연결 중인 사람을 포함해 최대 60명 보관한다. 상한에 도달하면 오프라인 중 오래된 사람부터 정리한다. 방이 만료되면 명단과 재접속 식별 정보도 함께 삭제한다.
- 참가자는 같은 브라우저에서 공유하는 방별 비공개 토큰으로 새 탭·재접속 시 같은 ID를 복원한다. 기존 탭 세션의 증명도 공유 저장소에 증명이 없으면 이어받는다. 서버에는 해시만 보관하고 초대 주소·공유 상태·추첨 기록에 토큰을 넣지 않는다. 공유 저장소가 막히면 탭 세션, 두 저장소 모두 막히면 메모리로 유지한다. 다른 브라우저·저장소 삭제는 새 참가자가 될 수 있다. 이 식별은 로그인이나 다른 기기로의 계정 복구가 아니다.

### 현재 결과의 up/down 피드백

[추첨 후 피드백 이슈 #20](https://github.com/acee90/random-number-generator/issues/20)의 기능이다. 추첨 시작 당시 명단의 방장과 일반 참가자는 룰렛 공개가 끝난 현재 결과에 **좋아요 / 싫어요** 중 한 표만 제출한다. 서버가 승인한 첫 표는 취소·변경할 수 없고, 이름 변경·다중 연결·복귀·서버 재시작 뒤에도 같은 참가자의 표를 유지한다. 방장은 집계·투표 당시 이름·반응 시간을 확인하고 **다음 게임 대기 화면으로**를 눌러 결과를 기록에 보관한 뒤 다음 추첨을 별도로 시작한다. 추첨 시작 후 입장한 새 참가자는 현재 회차에 투표할 수 없고 다음 회차부터 참여한다. 원래 참가자는 인증된 재입장 후에도 투표 자격을 유지한다. 반응 시간은 서버 수신 시각에서 공통 결과 공개 시각을 뺀 값이므로 네트워크 지연이 포함되며 버튼 입력 속도를 정밀 측정한 값은 아니다.

30초 같은 투표 시간제한은 없다. 방장 본인의 표가 처리 중일 때는 **다음 게임 대기 화면으로**를 잠그고 승인·실패가 확인된 뒤 해제한다. 다른 탭의 대기 복귀와 표가 경합하면 서버의 처리 순서를 따른다. 방장이 대기 복귀를 누르면 현재 결과와 투표를 한 번 복사해 확정 기록으로 보관하고 피드백을 닫는다. 결과 상태의 직접 시작 요청은 거절하며, 대기로 돌아온 뒤 별도로 시작해야 한다. 다음 추첨 준비가 실패해도 확정 기록은 다시 열지 않는다. 기록 상세에는 고정된 집계와 명단만 표시하며 투표 버튼은 없다. 이미 확정된 기록과 당시 후보·확률·참가자 정보는 이후 투표로 수정하지 않는다. 이전 버전에서 이미 기록으로 보관한 현재 회차도 읽기 전용이다.

현재 결과는 당첨 이름을 가장 크게, 분류는 보조 정보로 표시하고 긴 이름은 줄바꿈한다. 그 아래 큰 투표 버튼과 넓어진 집계를 배치하며 방장의 대기 복귀 버튼은 집계 아래 별도 행동으로 둔다. 좋아요·싫어요 팀을 좌우 50:50으로 나누고 팀원·전체 반응 속도 순위·시간을 펼침 없이 표시한다. 좁은 화면에서는 결과가 전체 폭을 쓰고 당첨 제외 패널이 아래로 이동한다. 반응 시간이 같으면 서버 기록 순서를 유지하며 기록 원본은 수정하지 않는다. 결과 복사·추첨 정보 버튼은 현재 결과 화면에서 제거했다. 새 표가 서버에서 승인되어 집계가 늘어날 때 해당 팀의 아이콘·숫자에 팝/파티클 효과를 표시한다. 처음 열거나 재접속·다른 회차·확정 기록을 볼 때는 기존 표에 효과를 재생하지 않는다. 동작 줄이기 설정에서는 슬라이드와 투표 효과를 사용하지 않는다.

투표 자격은 서버에 고정한 추첨 시작 시점의 참가 명단으로 검사한다. 최근 참가자 목록에서 빠져도 현재 회차의 참가 명단, 현재·보관 회차의 투표 또는 현재 후보 소유권이 남아 있는 동안 해당 재접속 매핑을 유지해 기존 참가자의 복귀와 첫 표를 보존한다. 명단이 없는 이전 결과는 신규 투표를 허용하지 않는다. 투표로 추첨 확률을 바꾸거나 자동 재추첨하지 않는다. 방 생성 후 24시간이라는 기존 이용 기간과 기록 20개 보관 한도는 그대로 적용한다.

추첨 기록은 요청 시점의 후보 목록·후보별 균등 확률·참가자 명단·요청 시각을 고정한다. 이후 후보 편집·이름 변경·새 참가자가 생겨도 당시 기록은 바뀌지 않는다. 난수 결과 생성 시각·공통 룰렛 시작 시각·공개 예정 시각·실제 난수 출처·회차 ID도 상세 보기에서 확인한다. 표시 확률은 당시 후보 수 기준 `1/N`이며 백분율 표시는 반올림한다.

결과 주화면의 **이번 추첨 결과**는 음식점·분류·투표와 방장의 다음 게임 버튼을 중심으로 제공한다. 자세한 정보는 **결과 히스토리의 회차를 눌러 여는 상세 창**에서 확인한다. PC에서는 왼쪽 열에 맞춘 별도 창으로 채팅을 계속 사용할 수 있고, 모바일에서는 닫기와 본문 스크롤을 갖춘 다이얼로그로 표시한다. 열린 회차는 선택 시 복사한 스냅샷으로 고정한다.

모바일의 추첨/채팅 전환 탭을 없애고 위쪽 추첨·투표와 아래쪽 채팅을 동시에 표시한다. 추첨·후보 목록과 채팅 메시지는 각각 스크롤하며 채팅 입력창은 화면 안에 유지한다. 낮은 가로 화면은 좌우 배치를 사용한다. 키보드로 가용 높이가 줄면 화면 높이와 영역 비율을 조정하고, 입력 중에는 로고·날짜·프로필을 잠시 접어 공간을 확보한다. 채팅 입력 중 추첨이 끝나도 입력 포커스와 작성 내용은 유지한다. 구현·운영 반영 상태는 [#32](https://github.com/acee90/random-number-generator/issues/32)에서 구분한다.

모바일에서 투표하면 버튼 영역을 높이와 투명도 애니메이션으로 접고, 집계의 선택한 팀을 진한 배경·체크·‘내 선택’으로 표시한다. 서버 확인 전에도 즉시 반영하며 거절·시간 초과로 임시 선택이 취소되면 버튼을 다시 펼친다. 키보드로 버튼을 눌렀다면 선택한 팀 집계로 포커스를 이어 준다. PC의 큰 버튼은 유지하고, 동작 줄이기 설정에서는 즉시 접는다.

기존 회차에 참가자나 요청 시각이 기록되지 않았다면 없는 정보로 안내하고 현재 명단을 대입하지 않는다. 원시 시드·난수 원본 바이트·외부 API 키는 저장하거나 공유하지 않는다. 방장만 추첨을 시작할 수 있으며 참가자의 직접 요청도 서버가 거부한다.

## Cloudflare 구성

기존 PartyKit 호스팅은 2026-10-23 종료되었다. [공식 안내](https://blog.partykit.io/posts/hosted-platform-shutdown)에 따라 **PartyServer + PartySocket**을 기존 Cloudflare Workers 계정에서 실행한다. 별도의 `partykit.dev` 서비스나 PartyKit 배포는 사용하지 않는다.

- `src/worker.ts`: TanStack 요청 처리와 방 생성·WebSocket 경로를 연결하는 Worker 진입점.
- `POST /api/lunch/rooms`: 같은 출처의 JSON 요청으로 방을 생성한다. 4KiB 제한을 적용하며 후보 선택 생략은 빈 목록, 명시된 기존 샘플 ID는 호환 검증한다. 입장 후 임의 후보를 편집하는 계약과 구분한다.
- `/parties/lunch-rooms/<UUID>`: 같은 출처의 WebSocket 연결만 허용한다. 공개 HTTP 초기화 경로는 없다. `room-edit` 전체 편집 요청은 최대 256KiB, 나머지 요청은 4KiB, 서버 응답은 8MiB의 UTF-8 JSON 한도를 적용한다.
- `LunchRooms`: `LunchRoomServer` SQLite Durable Object 바인딩. 방마다 하나의 객체가 상태와 WebSocket을 관리하며 hibernation과 alarm을 사용한다.
- `lunch-rooms-v1` migration이 최초 배포 시 클래스를 만든다. 기존 KV 바인딩과 난수 API 키는 그대로 사용한다. 별도의 채팅 API 키는 필요 없다.

### 변경 요청·충돌·호환성

접수 전환·후보 추천/삭제·후보 편집·게임 필터·옵션·제외 초기화는 요청 ID와 ACK를 사용한다. 같은 참가자의 같은 내용·요청 ID 재시도는 다시 적용하지 않고, 같은 ID의 다른 내용은 거절한다. 마감·옵션·초기화·추첨 확인은 최신 조건 버전, 전체 후보 편집은 기준 후보 버전을 검사한다. 필터는 후보 준비 화면에서만 변경하며 원본 후보·`listVersion`을 유지하고 추첨 조건 `revision`을 갱신한다. 추첨 준비 중에도 채팅·ping은 계속 처리한다. 저장 실패로 결과가 확정되지 않으면 기존 제외 내역을 유지하며, 공개되지 않은 당첨 결과를 임의로 복원하지 않는다.

이 lifecycle 변경 명령은 **방의 24시간 수명 동안 성공한 고유 요청 합계 2,000건**까지 허용한다. 동일 요청 재시도와 거절된 요청은 합계에 추가하지 않는다. 한도에 도달하면 새 접수 전환·후보 편집·옵션·초기화 요청에 `REQUEST_LIMIT`을 반환하고 새 방을 안내한다. 채팅·결과 피드백·기존 조건의 추첨 시작·결과의 대기 복귀는 이 변경 요청 합계와 별개다.

버전과 ACK가 없는 기존 `candidates` 전체 교체 명령은 `CLIENT_UPGRADE_REQUIRED`로 거절하고 새로고침을 안내한다. 배포 전 브라우저 탭의 오래된 편집 목록이 새 추천을 덮어쓰지 않도록 서버에서 차단한다. 이전 저장 형식의 `waiting + 현재 결과`는 결과 단계로 읽으며, 과거 회차에 없던 제외 옵션·내역을 만들어 넣지 않는다.

## 로컬 확인과 배포

```sh
npm install
npm run cf-typegen
npm run dev
```

`http://localhost:3000/`에서 방 이름·닉네임·후보를 입력해 방을 만든 뒤 초대 링크를 다른 탭이나 브라우저로 연다. 입장 전 닉네임 확인·중복 거절/재시도·이름 변경, 방장·참가자 표시, 양방향 채팅, 방장 추첨, 진행 중 새로고침, 동일 결과와 기록을 확인한다. 생성 전 작성·불러오기와 생성 후 룰렛 대기, 개인 사본 저장·불러오기·삭제와 실패 시 초안 보존, 대기→후보·필터 편집→마감, 대기의 후보·옵션 읽기 전용, 대기→후보 편집→접수→접수 종료→재개→마감과 접수 중 직접 마감, 페이지 내 후보 초안·충돌과 우상단 방 설정의 독립 변경, 결과→명시 대기→별도 시작, 제외 ON/OFF·확인 취소·초기화와 0/1개 복구, 페이지·채팅의 스크롤도 확인한다.

결과 보완에서는 방장·참가자의 1회 표와 방장 표 처리 중 이동 잠금, 승인·실패 뒤 해제, 확정 기록의 읽기 전용을 확인한다. 당첨 제외는 차수·시각·최근순과 긴 목록 스크롤, 후보 필터 사유의 분리, OFF 성공·초기화 뒤 차수 유지, 기록 20개 초과와 이전 저장본의 불완전 차수·없는 시각 표시를 함께 검증한다. 320px·긴 당첨 이름에서도 제목·투표·집계·다음 행동을 사용할 수 있어야 한다.

방장이 나갔을 때 승계되지 않는지, 전원이 나간 뒤에도 만료 전 재입장할 수 있는지, 같은 브라우저에서 방장 권한이 복원되는지 확인한다. 고정 만료와 데이터 삭제는 서버 시각을 제어하는 테스트로 검증한다. 로컬 Durable Object는 `.wrangler`에 저장되어 개발 서버를 다시 켜도 유지된다. 저장 데이터는 Git에서 제외된다.

```sh
npm test
npx tsc --noEmit
npm run build
```

기존 GitHub 연결 Workers 배포 또는 `npm run deploy`로 Worker와 Durable Object migration을 함께 배포한다. Wrangler CLI 직접 배포에는 해당 Cloudflare 계정 인증이 필요하다. 로컬 방과 배포한 방은 서로 다른 저장소이며 URL도 공유되지 않는다.

처음 `lunch-rooms-v1`을 적용할 때 Cloudflare의 브랜치 미리보기 명령인 `wrangler versions upload`는 미적용 Durable Object migration 오류로 실패할 수 있다. 먼저 검증한 버전을 `wrangler deploy`로 정식 배포해 새 SQLite 클래스를 만든 뒤 미리보기 빌드를 다시 실행한다. 이미 빌드한 결과를 그대로 배포할 때는 `npx wrangler deploy --config dist/server/wrangler.json --keep-vars`를 사용한다. 이후 migration 변경이 없는 버전은 기존 미리보기 업로드를 사용할 수 있다. 새 migration을 추가할 때마다 이 순서를 확인한다.


## 방장의 명시적 방 종료 (로컬 구현, 2026-11-17)

진행 상태와 완료 기준은 [방 수명 정책 #50](https://github.com/acee90/random-number-generator/issues/50)에서 관리한다. 이 설명은 로컬 구현이며 운영 배포 완료를 뜻하지 않는다.

방장은 **방 설정 → 방 종료**에서 전체 참가자의 이용 종료·재입장 불가·미저장 변경 손실을 확인한 뒤 방을 종료할 수 있다. 취소하면 설정과 입력을 유지한다. 참가자에게는 종료 버튼을 제공하지 않으며, 서버도 인증된 방장 ID를 검사한다. 추첨 준비·진행 중에는 종료를 차단한다. 새로고침, 네트워크 단절, 방장의 단순 퇴장은 명시적 종료로 처리하지 않는다.

`room-close` 명령은 기존 서버 변경 큐에서 직렬화한다. `closed` 상태를 저장한 뒤 요청 ACK, 종료 스냅샷, 전체 연결 종료를 전달한다. 저장 실패 시 직전 상태로 복구하고 종료하지 않는다. 종료 상태는 재시작 이후에도 유지하며 입장 정보·닉네임 확인은 `410 ROOM_CLOSED`, WebSocket은 종료 오류로 거절한다. 클라이언트는 재연결을 멈추고 새 방 만들기를 안내한다.

종료는 즉시 이용을 막지만 저장 데이터를 즉시 삭제하는 기능은 아니다. 생성 후 24시간인 기존 만료 시각은 유지하며 해당 시점의 기존 만료 경로에서 방 데이터와 alarm을 정리한다. 빈 방 자동 정리와 방장 부재 자동 종료 정책은 이번 범위에 포함하지 않는다.


## 종료된 방의 기록 조회 (로컬 구현)

진행은 [#75](https://github.com/acee90/random-number-generator/issues/75)에서 관리한다. 명시적 종료 후에도 원래 만료 시각까지 기존 방장/참가자가 같은 브라우저에 보관한 인증으로 최근 20개 추첨(마지막 결과 포함)을 확인하고 TXT로 저장할 수 있다. 당시 후보·확률·참가자·투표를 포함하고 채팅과 인증값은 포함하지 않는다. 영구 보관이나 만료 연장은 추가하지 않는다.

같은 출처의 `POST /api/lunch/rooms/<UUID>/history` 본문에 기존 hostToken 또는 guestToken을 전달한다. 서버는 기존 방장 해시/참가자 매핑을 검사하며, 응답은 방 이름·만료 시각·읽기 전용 추첨 목록으로 제한하고 캐시하지 않는다. 인증 누락/위조는403, 진행 중인 방은409, 만료는410으로 거절한다. HTTP 조회는 presence·활동·만료를 변경하지 않는다. 입장 정보와 닉네임 확인의410 및 WebSocket 재입장 거절은 유지한다. 새로고침의 입장 화면과 종료 직후 화면 모두 같은 기록 컴포넌트를 사용한다.
