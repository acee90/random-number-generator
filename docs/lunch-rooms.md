# 실시간 점심 추첨방

개발 계획과 진행 상태는 [GitHub 전체 로드맵 #7](https://github.com/acee90/random-number-generator/issues/7), 최신 운영 반영은 [출시 이슈 #8](https://github.com/acee90/random-number-generator/issues/8)에서 관리한다. 이 문서는 현재 로컬에 구현된 방의 동작과 운영 설명을 보관하는 보조 자료다.

현재 경로는 `/`의 시작 방식 선택, `/create`의 방 정보 입력·생성, `/solo`의 혼자 추첨, `/tools?tool=number|lotto|pension`의 번호 도구다. 홈에는 방 생성 폼을 두지 않고 **방 만들기**를 누르면 별도 화면에서 방 이름·닉네임을 입력한다. 기존 생성 검증·오류 재시도·기본 후보를 그대로 사용하며, 생성 화면은 검색 색인에서 제외한다. [홈 단계 분리 이슈 #34](https://github.com/acee90/random-number-generator/issues/34)에서 구현·배포 상태를 관리한다. 기존 `/lunch`는 `/`로 이동시키며 `/lunch-room/<UUID>` 초대 주소는 유지한다. 상세 설계는 [점메추 정보 구조 문서](jeommechu-ia-plan.md)를 참고한다.

현재 기본 목록은 사용자 제공 `회사주변_음식점_목록.xlsx`의 `회사 주변 음식점!A6:C112`에 있는 107곳·11개 분류다. 원본 순서를 유지하며 메뉴는 임의로 추가하지 않는다. 분류 미확인 2곳은 원본의 `확인 불가`를 유지하고 거리 미확인 1곳은 거리 값을 생략한다. 새 방과 단독 추첨의 전체 후보가 이 목록을 사용한다. [데이터 갱신 이슈 #17](https://github.com/acee90/random-number-generator/issues/17)에서 관리하며, 사용자 요청에 따라 이번 갱신에서 기존 방 검증·이관은 제외한다.

**초대 링크 복사**로 보낸 주소를 열면 닉네임 설정 → **입장하기** → 룰렛·채팅 순서로 참여한다. 저장된 이름은 입력란에 미리 채우기만 하고 자동 참가하지 않는다. 입장 전에는 WebSocket 연결이나 참가자 등록을 하지 않는다. 방 생성 화면에서 이미 닉네임을 정하고 **방 만들고 입장하기**를 누른 경우에만 메모리에 30초간 유지하는 일회성 입장 요청으로 중복 입력을 생략한다. 이 요청은 URL·브라우저 저장소에 남기지 않으며 새로고침·새 탭에서는 다시 닉네임을 확인한다. [닉네임 입장·중복 처리 이슈 #19](https://github.com/acee90/random-number-generator/issues/19)에서 관리한다.

닉네임은 NFKC 정규화와 앞뒤 공백 제거 후 1~12자(UTF-16)이며 제어·숨김 문자는 허용하지 않는다. 같은 방에서 온라인·자리비움 상태인 서로 다른 참가자는 대소문자를 포함해 정규화 기준으로 같은 이름을 쓸 수 없다. 오프라인 이름은 재사용할 수 있고, 복귀할 때 이미 사용 중이면 입력 화면에서 다른 이름으로 재시도한다. 인증된 동일 참가자의 다중 연결은 허용하며 이름만 같다고 신원을 합치거나 방장 권한을 주지 않는다. 서버가 승인한 이름만 표시·저장한다. 명시적인 이름 선택은 `updateName: true`로 보내고 이후 자동 재연결은 서버의 최신 이름을 복원한다.

입장 후 이름은 채팅 입력창 근처의 내 프로필에서 바꾼다. 채팅 공간·프로필 편집·참가자 상태 개선은 [GitHub 이슈 #14](https://github.com/acee90/random-number-generator/issues/14), 결과·상세 기록·후보 목록 배치와 닉네임 제한은 [GitHub 이슈 #15](https://github.com/acee90/random-number-generator/issues/15)에서 관리한다.

입장 화면에서는 입력을 350ms 멈추면 닉네임 사용 가능 여부를 자동 확인한다. 한글 조합 중에는 기다리고 확인 중에는 스피너와 상태 문구를 표시한다. 확인·중복·오류 상태에서는 입장을 막고 사용 가능 상태에서만 제출한다. 입력 변경 시 이전 요청을 취소하고 늦은 응답을 무시한다. 확인 요청은 같은 출처의 `POST /api/lunch/rooms/<UUID>/nickname-availability`로 보내며 참가자 등록·채팅·활동·만료 시각을 바꾸지 않는다. 본인 제외를 위한 비공개 증명은 요청 본문에만 넣고 응답에는 정규화된 이름과 가능 여부만 담는다. 확인 직후 다른 참가자가 먼저 입장할 수도 있으므로 실제 입장에서 중복을 다시 검사한다. 관련 진행은 [자동 중복 확인 이슈 #23](https://github.com/acee90/random-number-generator/issues/23)에서 관리한다.

입장·채팅의 렌더 비용은 [성능 개선 이슈 #25](https://github.com/acee90/random-number-generator/issues/25)에서 관리한다. 정적인 룰렛 SVG와 후보 목록은 실제 표시 내용이 같으면 재사용하고, 회전·버튼·권한·체크 상태와 최신 콜백은 계속 갱신한다. 첫 입장 화면에는 서버가 승인한 선택 목록을 바로 표시한다. 개발용 Profiler의 계산 횟수와 실제 네트워크 대기는 구분한다. 이 개선은 닉네임 확인을 생략하거나 서버의 중복·권한 검사를 우회하지 않는다.

## 화면 배치 전환 기준

- 데스크톱은 왼쪽에 **룰렛 / 결과** 보기, 오른쪽에 채팅을 둔다. 보기 전환은 같은 회차의 표시만 바꾸며 재추첨하지 않는다.
- 후보 목록은 룰렛·결과 영역 아래에 항상 한 열로 제공한다. 후보 목록 안에는 별도 스크롤을 만들지 않고 페이지를 따라 내려간다. 방장은 대기 중 편집·적용하고 참가자는 현재 선택 목록을 읽는다.
- 페이지와 왼쪽 콘텐츠의 세로 스크롤을 허용한다. 채팅은 데스크톱에서 고정 위치를 유지하고 메시지 목록 안에서 스크롤한다. 좁은 화면에서는 세로 흐름으로 배치하며 후보를 계속 제공한다.
- `/solo`의 개인 기록과 방의 공동 기록은 서로 다른 저장소와 화면이다.

후보 조작의 접근성은 [GitHub 이슈 #16](https://github.com/acee90/random-number-generator/issues/16)에서 관리한다. 후보를 편집하는 동안 섹션 상단의 분류·선택 수·적용/변경 취소 툴바가 왼쪽 열 안에서 따라온다. 긴 목록의 끝까지 내려가지 않고 적용할 수 있으며 후보 목록의 세로 내부 스크롤은 추가하지 않는다. 작은 화면의 분류 버튼은 가로로 넘겨 볼 수 있다.

방장은 여러 분류를 켜거나 끄며 실제 추첨 후보를 편집한다. 같은 페이지에서 분류를 다시 켜도 개별로 제외한 음식점은 유지한다. 적용 전 선택 수와 서버에 실제 적용된 수를 구분하며, **후보 적용** 전에는 공동 룰렛의 목록이 바뀌지 않는다. **변경 취소**는 서버에 적용된 목록으로 돌아간다. 참가자의 분류 버튼은 목록 보기만 거르고 실제 추첨 후보를 바꾸지 않는다. 참가자에게는 표시 수와 실제 후보 수를 함께 안내한다.

이 배치는 로컬 구현 기준이다. 운영에 반영한 버전과 확인 결과는 출시 이슈에 기록한다.

## 동작과 보관 범위

- 방장만 후보를 바꾸거나 추첨을 시작한다. 참가자는 채팅과 공동 시청을 할 수 있다.
- 서버가 후보 목록·회차 ID·난수 결과·시작 시각·회전각을 한 번 결정한다. 브라우저는 같은 7.2초 애니메이션을 경과 시점에 맞춰 재생한다. 연결과 기기 차이에 따른 프레임 단위 차이는 있을 수 있다.
- 진행 중 입장하거나 재접속하면 같은 회차와 타임라인을 복원한다. 완료한 현재 결과는 방장이 투표를 종료할 때 투표와 함께 확정 기록으로 보관하고 모두 다음 추첨을 준비한다. 단독 추첨의 브라우저 기록과는 별개다.
- 난수는 기존 요청별 ANU → Random.org → Web Crypto 경로를 사용한다. 실제 사용한 출처를 결과에 표시한다.
- 최대 30명, 메시지 500자·750ms 전송 간격, 최근 채팅 100개·확정 결과 20개와 현재 회차를 보관한다.
- 방의 만료 시각은 **생성 시각 + 24시간**으로 고정한다. 입장·채팅·추첨·방장 복귀로 연장하지 않는다. 방장이나 전원이 나가도 즉시 삭제하지 않으며, 남은 시간 안에 같은 링크로 복귀할 수 있다.
- 방장 권한은 브라우저에 보관한 별도 토큰으로 확인한다. 서버에는 SHA-256 해시만 저장하며 참가 링크·공유 상태에는 토큰을 넣지 않는다. 동일 브라우저에 증명이 남아 있으면 재접속 시 서버가 확인하고 권한을 복원한다. 방장 브라우저의 저장소를 지우거나 다른 브라우저로 옮기면 증명 없이 권한을 복원할 수 없다.
- 방장이 나갔다고 참가자에게 권한을 자동 이전하지 않는다. 참가자는 채팅하며 기다릴 수 있고, 새 추첨과 후보 변경은 방장이 돌아온 뒤 가능하다. 닉네임이나 입장 순서로 방장을 정하지 않는다. 계정 로그인·권한 이전은 이번 범위에 포함하지 않는다.
- 초대 링크는 옵션 없는 일반 방 주소를 공유한다. 기존 `?guest=1` 주소로 들어와도 브라우저에 유효한 방장 증명이 있으면 서버에 확인해 방장으로 복귀한다. 증명이 없으면 참가자로 입장한다. URL의 옵션이나 닉네임만으로 권한을 부여하지 않는다. 관련 수정: [방장 복귀 버그 #18](https://github.com/acee90/random-number-generator/issues/18).
- 링크를 아는 사람은 참가할 수 있다. 채팅은 텍스트로 표시하며 파일 업로드·개인 메시지는 지원하지 않는다.

## 방의 수명과 복귀

| 상황 | 유지되는 것과 처리 | 화면 안내 |
| --- | --- | --- |
| 방장이 나감 | 원래 만료 시각·후보·채팅·결과를 유지한다. 자동 승계는 없다. | 방장 오프라인, 참가자는 채팅하며 대기 |
| 모두 나감 | 생성 후 24시간까지 보관한다. Durable Object의 휴면은 삭제가 아니다. | 만료 전 같은 링크로 재입장 가능 |
| 일시적인 연결 끊김 | 같은 회차·후보·타임라인·기록으로 재연결한다. | 다시 연결 중, 연결 전 조작 제한 |
| 생성 후 24시간 경과 | 서버가 저장한 방 데이터·채팅·결과·방장 해시와 alarm을 삭제하고 연결을 종료한다. | 이용 종료, 새 방 만들기로 복귀 |
| 없거나 이미 삭제된 방 | 이전 UUID를 다시 생성하거나 기록을 복원하지 않는다. | 방을 찾을 수 없음, 새 방 만들기로 복귀 |

만료는 서버가 판단하며, 브라우저 화면을 닫거나 개인 저장소를 지우는 것과 별개다. 재입장해도 만료 시각은 바뀌지 않는다. 만료 후에는 기존 링크를 재사용해 새 방을 되살리지 않고, 새 방 생성으로 새 UUID와 새로운 24시간을 시작한다. 방 정보가 삭제된 뒤에는 예전 링크에서 ‘만료’와 ‘없음’을 구분하지 못할 수 있으므로 두 경우 모두 새 방 생성으로 안내한다.

현재 서버는 만료 데이터를 삭제하고 클라이언트는 종료 안내와 자동 재연결 중단을 처리한다. 종료·없는 방·권한 복원 실패에서 **새 방 만들기**로 이어지는 화면은 이번 정보 구조 전환의 완료 기준에 포함한다. 별도의 영구 기록 보관이나 자동 방장 승계는 추가하지 않는다.

## 채팅과 회차별 상세 기록

새 닉네임은 방 생성·입장·변경·브라우저 저장·서버 검증 모두 최대 12자로 제한한다. HTML `maxLength`와 같은 UTF-16 길이 기준이며 보조 평면 이모지는 두 단위로 센다. 기존의 긴 현재 이름은 이모지를 반으로 자르지 않고 12자 안으로 이관한다. 과거 채팅과 회차에 기록된 이름은 원문을 보존한다.

내가 보낸 메시지는 오른쪽, 다른 참가자의 메시지는 왼쪽에 표시한다. 연속된 같은 사람의 같은 분 대화는 이름과 시각 중복을 줄이고 시스템 알림에서 묶음을 나눈다. 닉네임 편집과 참가자 목록은 대화를 밀지 않는 작은 창으로 연다. 전송 버튼은 입력창 옆에 두며 Enter 전송·Shift+Enter 줄바꿈과 한글 조합 입력을 유지한다. 입장·퇴장·이름 변경·추첨 시작/완료/실패는 서버가 만든 시스템 메시지로 채팅과 같은 최근 100개 한도 안에 보관한다. 연결을 잃은 브라우저에는 자체 연결 끊김/복구 안내도 표시한다. 시스템 알림을 클라이언트가 임의로 만들어 다른 참가자에게 보낼 수는 없다.

### 참가자 접속 상태

- 초록 점과 **온라인**은 연결되어 있고 최근 5분 안에 활동한 사람, 노랑 점과 **자리비움**은 연결은 있지만 5분 이상 활동이 없는 사람, 빨강 점과 **오프라인**은 마지막 연결이 종료된 사람이다. 색과 상태 이름을 함께 제공한다.
- 서버 시각을 기준으로 판단한다. 키보드·포인터 이동/누름·직접 스크롤 같은 활동을 최대 15초 간격으로 전달하므로 마지막 활동 시각에 그 정도 차이가 있을 수 있다. 브라우저가 오래 멈춰 마지막 입력 이후 30초 넘게 지연된 대기 활동은 보내지 않는다. 연결 유지 ping, 메시지 도착에 따른 자동 스크롤, 단순한 탭 표시 변경은 활동으로 보내지 않는다. 연결 장애는 서버가 종료를 감지한 뒤 오프라인으로 바뀐다.
- 같은 참가자의 연결이 여러 개면 하나라도 최근 활동한 연결이 있는 동안 온라인이다. 방의 현재 참가자 수·추첨 당시 명단에는 연결된 사람만 포함하고 자리비움도 연결 인원으로 센다.
- 최근 참가자 명단은 연결 중인 사람을 포함해 최대 60명 보관한다. 상한에 도달하면 오프라인 중 오래된 사람부터 정리한다. 방이 만료되면 명단과 재접속 식별 정보도 함께 삭제한다.
- 참가자는 같은 브라우저에서 공유하는 방별 비공개 토큰으로 새 탭·재접속 시 같은 ID를 복원한다. 기존 탭 세션의 증명도 공유 저장소에 증명이 없으면 이어받는다. 서버에는 해시만 보관하고 초대 주소·공유 상태·추첨 기록에 토큰을 넣지 않는다. 공유 저장소가 막히면 탭 세션, 두 저장소 모두 막히면 메모리로 유지한다. 다른 브라우저·저장소 삭제는 새 참가자가 될 수 있다. 이 식별은 로그인이나 다른 기기로의 계정 복구가 아니다.

### 현재 결과의 up/down 피드백

[추첨 후 피드백 이슈 #20](https://github.com/acee90/random-number-generator/issues/20)의 기능이다. 추첨 시작 당시 입장한 참가자만 룰렛 공개가 끝난 현재 결과에 **좋아요 / 싫어요** 중 한 표만 제출한다. 서버가 승인한 첫 표는 취소·변경할 수 없고, 이름 변경·다중 연결·복귀·서버 재시작 뒤에도 같은 참가자의 표를 유지한다. 방장은 투표하지 않고 집계·투표 당시 이름·반응 시간을 보고 ‘투표 종료하고 다음 게임’으로 결과를 기록에 보관한 뒤 다음 추첨을 별도로 시작한다. 추첨 시작 후 입장한 새 참가자는 현재 회차에 투표할 수 없고 다음 회차부터 참여한다. 원래 참가자는 인증된 재입장 후에도 투표 자격을 유지한다. 반응 시간은 서버 수신 시각에서 공통 결과 공개 시각을 뺀 값이므로 네트워크 지연이 포함되며 버튼 입력 속도를 정밀 측정한 값은 아니다.

30초 같은 투표 시간제한은 없다. 방장이 투표를 종료하거나 호환되는 클라이언트에서 다음 추첨을 시작하면 그 직전 결과와 투표를 한 번 복사해 확정 기록으로 보관하고 현재 투표를 닫는다. 다음 추첨 준비가 실패해도 확정 기록은 다시 열지 않는다. 기록 상세에는 고정된 집계와 명단만 표시하며 투표 버튼은 없다. 이미 확정된 기록과 당시 후보·확률·참가자 정보는 이후 투표로 수정하지 않는다. 이전 버전에서 이미 기록으로 보관한 현재 회차도 읽기 전용이다.

현재 결과는 큰 투표 버튼과 선택 표시, 집계를 중심으로 표시한다. PC에서는 집계가 오른쪽으로 펼쳐지고 좁은 화면에서는 결과 아래에 배치한다. 좋아요·싫어요 팀을 좌우 50:50으로 나누고 팀원·전체 반응 속도 순위·시간을 펼침 없이 표시한다. 반응 시간이 같으면 서버 기록 순서를 유지하며 기록 원본은 수정하지 않는다. 결과 복사·추첨 정보 버튼은 현재 결과 화면에서 제거했다. 새 표가 서버에서 승인되어 집계가 늘어날 때 해당 팀의 아이콘·숫자에 팝/파티클 효과를 표시한다. 처음 열거나 재접속·다른 회차·확정 기록을 볼 때는 기존 표에 효과를 재생하지 않는다. 동작 줄이기 설정에서는 슬라이드와 투표 효과를 사용하지 않는다.

투표 자격은 서버에 고정한 추첨 시작 시점의 참가 명단으로 검사한다. 최근 참가자 목록에서 빠져도 현재 회차의 참가 명단 또는 현재·보관 회차의 투표가 남아 있는 동안 해당 재접속 매핑을 유지해 기존 참가자의 복귀와 첫 표를 보존한다. 명단이 없는 이전 결과는 신규 투표를 허용하지 않는다. 투표로 추첨 확률을 바꾸거나 자동 재추첨하지 않는다. 방 생성 후 24시간이라는 기존 이용 기간과 기록 20개 보관 한도는 그대로 적용한다.

추첨 기록은 요청 시점의 후보 목록·후보별 균등 확률·참가자 명단·요청 시각을 고정한다. 이후 후보 편집·이름 변경·새 참가자가 생겨도 당시 기록은 바뀌지 않는다. 난수 결과 생성 시각·공통 룰렛 시작 시각·공개 예정 시각·실제 난수 출처·회차 ID도 상세 보기에서 확인한다. 표시 확률은 당시 후보 수 기준 `1/N`이며 백분율 표시는 반올림한다.

룰렛 위의 **이번 추첨 결과**는 음식점·분류·투표와 방장의 다음 게임 버튼을 중심으로 제공한다. 자세한 정보는 **결과 히스토리의 회차를 눌러 여는 상세 창**에서 확인한다. PC에서는 왼쪽 열에 맞춘 별도 창으로 채팅을 계속 사용할 수 있고, 모바일에서는 닫기와 본문 스크롤을 갖춘 다이얼로그로 표시한다. 열린 회차는 선택 시 복사한 스냅샷으로 고정한다.

모바일의 추첨/채팅 전환 탭을 없애고 위쪽 추첨·투표와 아래쪽 채팅을 동시에 표시한다. 추첨·후보 목록과 채팅 메시지는 각각 스크롤하며 채팅 입력창은 화면 안에 유지한다. 낮은 가로 화면은 좌우 배치를 사용한다. 키보드로 가용 높이가 줄면 화면 높이와 영역 비율을 조정하고, 입력 중에는 로고·날짜·프로필을 잠시 접어 공간을 확보한다. 채팅 입력 중 추첨이 끝나도 입력 포커스와 작성 내용은 유지한다. 구현·운영 반영 상태는 [#32](https://github.com/acee90/random-number-generator/issues/32)에서 구분한다.

모바일에서 투표하면 버튼 영역을 높이와 투명도 애니메이션으로 접고, 집계의 선택한 팀을 진한 배경·체크·‘내 선택’으로 표시한다. 서버 확인 전에도 즉시 반영하며 거절·시간 초과로 임시 선택이 취소되면 버튼을 다시 펼친다. 키보드로 버튼을 눌렀다면 선택한 팀 집계로 포커스를 이어 준다. PC의 큰 버튼은 유지하고, 동작 줄이기 설정에서는 즉시 접는다.

기존 회차에 참가자나 요청 시각이 기록되지 않았다면 없는 정보로 안내하고 현재 명단을 대입하지 않는다. 원시 시드·난수 원본 바이트·외부 API 키는 저장하거나 공유하지 않는다. 방장만 추첨을 시작할 수 있으며 참가자의 직접 요청도 서버가 거부한다.

## Cloudflare 구성

기존 PartyKit 호스팅은 2026-10-23 종료되었다. [공식 안내](https://blog.partykit.io/posts/hosted-platform-shutdown)에 따라 **PartyServer + PartySocket**을 기존 Cloudflare Workers 계정에서 실행한다. 별도의 `partykit.dev` 서비스나 PartyKit 배포는 사용하지 않는다.

- `src/worker.ts`: TanStack 요청 처리와 방 생성·WebSocket 경로를 연결하는 Worker 진입점.
- `POST /api/lunch/rooms`: 같은 출처의 JSON 요청으로 방을 생성한다. 4096바이트 제한과 고정 샘플 ID 검증을 거친다.
- `/parties/lunch-rooms/<UUID>`: 같은 출처의 WebSocket 연결만 허용한다. 공개 HTTP 초기화 경로는 없다.
- `LunchRooms`: `LunchRoomServer` SQLite Durable Object 바인딩. 방마다 하나의 객체가 상태와 WebSocket을 관리하며 hibernation과 alarm을 사용한다.
- `lunch-rooms-v1` migration이 최초 배포 시 클래스를 만든다. 기존 KV 바인딩과 난수 API 키는 그대로 사용한다. 별도의 채팅 API 키는 필요 없다.

## 로컬 확인과 배포

```sh
npm install
npm run cf-typegen
npm run dev
```

`http://localhost:3000/`에서 닉네임과 방 이름을 정해 방을 만든 뒤 초대 링크를 다른 탭이나 브라우저로 연다. 입장 전 닉네임 확인·중복 거절/재시도·이름 변경, 방장·참가자 표시, 양방향 채팅, 방장 추첨, 진행 중 새로고침, 동일 결과와 기록을 확인한다. 룰렛/결과 보기와 상시 후보 목록, 페이지·채팅의 스크롤도 확인한다.

방장이 나갔을 때 승계되지 않는지, 전원이 나간 뒤에도 만료 전 재입장할 수 있는지, 같은 브라우저에서 방장 권한이 복원되는지 확인한다. 고정 만료와 데이터 삭제는 서버 시각을 제어하는 테스트로 검증한다. 로컬 Durable Object는 `.wrangler`에 저장되어 개발 서버를 다시 켜도 유지된다. 저장 데이터는 Git에서 제외된다.

```sh
npm test
npx tsc --noEmit
npm run build
```

기존 GitHub 연결 Workers 배포 또는 `npm run deploy`로 Worker와 Durable Object migration을 함께 배포한다. Wrangler CLI 직접 배포에는 해당 Cloudflare 계정 인증이 필요하다. 로컬 방과 배포한 방은 서로 다른 저장소이며 URL도 공유되지 않는다.

처음 `lunch-rooms-v1`을 적용할 때 Cloudflare의 브랜치 미리보기 명령인 `wrangler versions upload`는 미적용 Durable Object migration 오류로 실패할 수 있다. 먼저 검증한 버전을 `wrangler deploy`로 정식 배포해 새 SQLite 클래스를 만든 뒤 미리보기 빌드를 다시 실행한다. 이미 빌드한 결과를 그대로 배포할 때는 `npx wrangler deploy --config dist/server/wrangler.json --keep-vars`를 사용한다. 이후 migration 변경이 없는 버전은 기존 미리보기 업로드를 사용할 수 있다. 새 migration을 추가할 때마다 이 순서를 확인한다.
